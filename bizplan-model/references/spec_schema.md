# 월별 사업계획 설계서 작성법

`Work/model_spec.json`에는 회사의 계정 매핑과 계획 가정을 적는다. 전체 작성 예시는 `assets/example_spec.json`의 가상회사 달구름키트다. `assets/spec.schema.json`은 JSON Schema 2020-12 형식이다. `scripts/spec_io.py`는 배포된 스키마를 로컬에서 읽고 Python 표준 라이브러리로 형식과 파일 간 관계를 검사한다.

정상 빌드는 `python -B scripts/build_model.py --spec Work/model_spec.json --data Work/normalized --out Work/model.xlsm`으로 실행한다. 콘솔에는 ASCII 완료·실패 요약과 경고 수가 나오며, 한글 경고·오류 전문은 기본적으로 산출 파일 옆의 UTF-8 `build_log.md`에 기록한다. `--log`로 실행별 로그 경로를 지정할 수 있다. 같은 폴더에서 산출 파일을 여러 개 만들고 각 로그를 보관하려면 서로 다른 로그명을 쓴다. 기존 산출 파일이 있으면 빌드 시작 때 `model.xlsm.prev`로 이동한다. 실패 시 산출 경로는 비어 있으므로 종료 코드와 로그를 확인하고 입력을 수정한 뒤 다시 빌드한다.

## 기간과 단위

| 필드 | 뜻과 예시 | 생략 시 |
|---|---|---|
| `company` | 표지에 표시할 회사명. 예시 `"가상회사 달구름키트"` | 필수 |
| `unit` | 표시 단위 하나에 해당하는 원 금액. 백만원이면 `1000000`, 원이면 `1`. 양의 정수 | `1000000` |
| `first_month` | 첫 실적 월. 예시 `"2026-01"` | 필수 |
| `last_actual` | 마지막 실적 월. 예시 `"2026-12"` | 필수 |
| `plan_end` | 마지막 추정 월. 예시 `"2027-12"` | 필수 |
| `statements.bs` | BS와 BS명세를 모델에 포함할지 정하는 불리언 | BS CSV가 있으면 `true`. 파일이 없으면 명시적으로 `true`를 적어도 결과는 `false`. 파일이 있어도 `false`로 생략 가능 |

새 동인·조달·세무 필드를 생략한 기존 설계서도 같은 CLI로 빌드할 수 있다. 기존 설계서의 법인세는 사업연도별 법정 누진세율로 다시 계산한다. 옛 단일 세율 입력은 경고 후 무시한다.

월은 두 자리 달을 포함한 `YYYY-MM` 문자열이다. `first_month ≤ last_actual < plan_end`를 충족해야 한다. Excel의 J열은 첫 실적 월이며 오른쪽으로 한 달씩 진행한다. 모든 금액은 설계서와 CSV에 원으로 적는다. 예컨대 월매출 320만원은 `3200000`이다. 엔진은 금액을 표시할 때 `Unit`으로 나눈다. 인원, 수량, 일수, 비율에는 단위 변환을 적용하지 않는다. 5%는 숫자 `0.05`로 적는다.

## 매출·비용 라인

`revenue_lines`에는 한 개 이상의 매출 라인을 적는다. `cost_lines`도 필수이며 비용이 없으면 빈 배열을 적는다. 각 라인에 다음 필드를 넣는다.

| 필드 | 뜻과 예시 | 생략 시 |
|---|---|---|
| `id` | 매출·비용 전체에서 유일한 연결 키. 예시 `"kits"` | 필수 |
| `label` | 모델에 표시할 항목명. 예시 `"키트 판매"` | 필수 |
| `accounts` | 같은 손익 구분 안에서 이 라인에 배정할 원천 계정명 배열. 예시 `["제품매출","상품매출"]`. 실적이 없는 신규 라인은 `[]` | 필수 |
| `basis` | 추정 근거. 원자료, 기준 기간, 산정 방법을 적는다. 예시 `"가상 판매계획의 월 판매 수량과 단가"` | 생략 또는 공백이면 경고 후 계속 |
| `driver` | 매출의 계산 유형. 아래 표의 매출 동인 중 하나 | 매출에 필수 |
| `section` | 비용의 손익 구분. `매출원가` 또는 `판관비`. 매출 라인은 자동으로 `매출`에 배정 | 비용에 필수 |
| `method` | 비용의 계산 방식. 아래 표의 비용 방식 중 하나 | 비용에 필수 |
| `params` | 선택한 동인·방식의 가정 객체 | `{}`. `pct_of_revenue`는 대상 매출 ID 필수. `mixed`와 `pct_of_line`도 대상 배열 필수 |

영업 계정은 `(section, account)` 단위로 정확히 한 라인에 배정한다. 매출원가와 판관비에 같은 계정명이 있어도 각 구분에서 따로 배정할 수 있다. 배정 계정은 실적 기간에 한 번 이상 나와야 한다. 금액이 전 기간 0이어도 손익 CSV에 등장하는 영업 계정은 정확히 한 라인에 배정한다. 원자료를 확인해 전 기간 0인 계정의 행을 모두 생략했다면 설계서의 `accounts`에서도 빼고, 신규 계획 라인은 `accounts: []`로 만든다. 서로 다른 달의 양수·음수가 연간 합계에서 상쇄된 계정은 실제 거래가 있는 계정이다. 영업외수익·영업외비용·법인세 계정은 실적 원천에 남긴다.

| 매출 driver | params에 넣을 값과 예시 | 생략 시 |
|---|---|---|
| `growth` | `base_monthly` 기준 월매출(원), `annual_growth` 연 성장률, `seasonal` 실적 계절성 사용 여부. 예시 `{"base_monthly":720000,"annual_growth":0.04,"seasonal":false}` | 금액·성장률 0, 계절성 false |
| `price_volume` | `quantity` 월 수량, `price` 개당 원 단가, `annual_growth` 수량의 연 성장률. 예시 `{"quantity":120,"price":18000,"annual_growth":0.08}` | 수량·단가·성장률 0. 선택 필드 `monthly`는 빈 객체, `seasonal`은 false. 아래 월별 수량·단가 절 참조 |
| `activity` | 월 활동량 × 활동당 판매 수량 × 개당 원 단가. 세 기준은 `params.activity`, `params.yield`, `params.price`에 각각 지정 | 세 기준 모두 `last_12m`. 연 증감률 0, 단가 조정 없음 |
| `contracts` | `new_monthly` 미식별 신규 계약 월매출(원). 예시 `{"new_monthly":300000}`. 확인된 계약은 CSV의 기간·월금액·확률로 계산 | 0 |
| `pct_of_line` | `line_ids`에 적은 다른 매출 라인의 당월 최종 금액 합계 × 부호 있는 `rate`. 예시 `{"line_ids":["kits"],"rate":-0.02}`는 키트 매출의 2% 에누리 | 대상 매출 ID 최소 하나 필수, 비율 0. 자기 참조·순환 불가 |
| `cohort` | `opening_customers` 기초 고객 수, `new_customers` 월 신규 고객 수, `churn` 월 이탈률(0~1), `arpu` 고객당 월매출(원). 예시 `{"opening_customers":80,"new_customers":6,"churn":0.025,"arpu":49000}` | 고객 수·이탈률·객단가 0. 신규 기대 고객의 `new_probability`는 1 |
| `manual` | `monthly` 추정 월별 매출(원). 예시 `{"monthly":{"2027-03":450000}}` | 빈 객체, 미입력 월 0 |

| 비용 method | params에 넣을 값과 예시 | 생략 시 |
|---|---|---|
| `pct_of_revenue` | `revenue_ids` 또는 `base_lines` 대상 매출 ID 배열, `rate` 지정 매출 합계 대비 비용 비율. 예시 `{"revenue_ids":["kits"],"rate":0.4}` | 대상 ID 최소 하나 필수, 비율 0 |
| `per_metric` | `metric` 지표 ID, `unit_cost` 물량당 원가(원/지표 단위, 숫자·월별 객체·`"actual"`), `annual_growth` 연 증감률 | 지표 필수, 단위원가 `"actual"`, 증감률 0 |
| `per_activity` | `base_lines`에 지정한 활동 매출 라인들의 활동량 합계 × `unit_cost`(원/활동). `annual_growth`도 지원 | 대상 활동 매출 ID 최소 하나 필수. 단위원가 `"actual"`, 증감률 0 |
| `consumption` | `metric`, `efficiency`(지표량/사용량), `price`와 `subsidy`(각각 원/사용량), `adjustments`(추정 월별 원 보정액), `actual_usage`(실적 월별 관측 사용량), `subsidy_link`(선택, 구매 단가 연동 보조). 효율·단가·단위 보조는 숫자 또는 월별 객체 | 지표·양의 효율·구매 단가 필수, 단위 보조와 보정액 0 |
| `fixed_inflation` | `base_monthly` 기준 월 비용(원), `annual_growth` 연 인상률. `monthly`에 추정 월별 인상 전 금액을 원 단위로 직접 넣을 수 있다. 예시 `{"base_monthly":500000,"annual_growth":0.02,"monthly":{"2027-02":450000}}` | 기준값과 인상률은 각각 0. 월별 입력이 비어 있으면 공통 기준값을 적용하고 명시한 0원은 그대로 쓴다. 직군 연동 시 같은 월별 금액으로 소급분을 계산한다. |
| `mixed` | `base_monthly` 고정비(원), `annual_growth` 고정분 연 인상률, `rate` 변동비율, `revenue_ids` 대상 매출 ID 배열 | 대상 최소 하나 필수, 나머지 0 |
| `pct_of_line` | `line_ids` 대상 매출·비용 ID 배열, `rate` 비율 | 대상 최소 하나 필수, 비율 0 |
| `per_headcount` | `role` 대상 직군, `monthly_cost` 1인당 월 비용(원). 예시 `{"role":"운영"}` | 직군 생략 시 전체 인원. 단가 생략 시 해당 인원계획의 급여를 사용. 명시적 0은 단가 0 |
| `manual` | `monthly` 추정 월별 비용(원). 예시 `{"monthly":{"2027-04":250000}}` | 빈 객체, 미입력 월 0 |

계약의 미식별 신규 월매출은 기본적으로 해당 월에만 발생한다. 구독처럼 계속 청구하면 `contracts.params.new_monthly_recurring=true`와 월 이탈률 `churn`(0~1, 생략 시 0)을 지정한다. 추정 신규 계약에서 이월되는 월매출은 전월 미식별 신규 매출 × (1 − 이탈률) + 당월 조정 신규 유입이다. 첫 추정 월의 이월액은 0이다. CSV에 이미 등록한 계약은 각 계약의 기간·확률로 계산한다. 매월 최종 매출에 별도로 더하는 확장 조정액은 다음 달에 이월하지 않는다.

특정 월에만 금액이 확정된 영업수입은 `driver:"manual"` 라인에 `params.monthly:{"2027-03":900000}`처럼 월별 원 금액을 적는다. 기본 가정으로 3월 매출은 90만원, 다른 추정 월은 0원이다. Excel의 해당 매출 상세 시트 ‘월 매출 계획’ 노란 행은 **표시 단위**다. `unit:1000`이면 3월 셀에 900을 입력한다. 영업외수익으로 분류한 금액은 `non_operating.income_monthly`를 사용한다.

### 기존 계약의 갱신

만료 후에도 같은 금액으로 갱신되는 계약은 해당 contracts 라인의 `params.renewal`에 `{"probability":0.8,"term_months":2}`처럼 생존 확률(0~1)과 갱신 기간(양의 정수 개월)을 함께 적는다. 생략하면 CSV에 적은 만료 월까지만 반영한다. 원계약은 만료 월까지 유효하고, 갱신 기대 매출은 익월부터 **만료 월 계약액 × 원계약 실현 확률 × 적용 갱신 확률의 갱신 회차 거듭제곱**이다. 월 100만원, 확정 계약, 2개월마다 80% 갱신이면 만료 다음 두 달은 각 80만원, 그 다음 두 달은 각 64만원이다. 실적 마감 월에 만료된 계약도 대상이다. 마감 전에 이미 종료된 계약은 되살리지 않는다.

`scenarios.Up.drivers.projects.renewal_probability`처럼 갱신을 설정한 계약 라인에 시나리오별 절대 확률을 적는다. 생략하거나 전제사항의 해당 시나리오 셀을 비우면 ‘기본 계약 갱신 확률’ 입력을 참조한다. 0을 적으면 해당 시나리오의 갱신 매출은 0이다. 추가 케이스는 선택된 시나리오를 따른다. 만료 월 계약액이나 기본 확률을 Excel에서 바꾸면 이후 갱신 금액도 바뀐다. 미확정 제외 여부는 원계약 실현 확률로 판정한다. 원계약이 확정이면 갱신 확률이 1 미만이어도 생존 확률을 적용해 갱신 기대 매출을 계산한다. 미식별 신규 매출은 앞 절의 별도 신규 유입 계산을 따른다.

### 월별 수량·단가와 계절성

아래는 매출 라인 하나의 예다. 실적 월 매출은 배정한 손익 계정 합계에서 읽는다. 실적 수량·단가 CSV는 판매 구성과 수량 계절성을 설명하는 보조 자료다.

```json
{"id":"kits","label":"키트 판매","accounts":["제품매출"],"driver":"price_volume",
 "params":{"quantity":100,"price":18000,"annual_growth":0.04,"seasonal":true,
           "monthly":{"2027-03":{"quantity":145},"2027-04":{"price":19000}}},
 "basis":"판매계획의 3월 수량, 4월 인상 단가와 전년도 월별 출하 수량"}
```

추정 월마다 수량과 단가를 각각 결정한다. `params.monthly`에는 수량 또는 단가 한쪽만 지정할 수 있다. 같은 월의 `sales_volume.csv` 값도 월별 지정값이다. 같은 필드가 양쪽에 있으면 일치해야 하며 서로 다른 값은 설계서 오류다. 생성된 매출 상세 시트에서 월별 수량과 단가는 별도 노란 행이다. 셀을 비우면 기준 가정으로 복귀하고 숫자 0을 입력하면 해당 월의 지정값 0을 사용한다.

전 추정 월의 수량·단가를 월별로 모두 제공하면 `quantity`, `price`, `annual_growth`는 생략하거나 0으로 둘 수 있다. 그 달의 명시값에는 기준 수량·단가나 연 성장률을 다시 적용하지 않는다. 예를 들어 어느 달에 수량 120개와 개당 단가 18,000원을 지정하면 매출 동인 금액은 2,160,000원이다. 월별 표가 끝난 뒤에도 계획을 연장하거나 엑셀에서 특정 달의 값을 비울 예정이면 그때 쓸 기준 수량·단가·연 성장률을 근거와 함께 입력한다.

1. 수량이 지정되면 해당 값을 쓰고, 비어 있으면 기준 수량 × 성장 배수 × 계절 지수를 쓴다. 성장 배수는 (1 + 연 성장률)의 경과 연도 수 제곱이다. 실적 마감과 같은 해는 0년, 이듬해 1월부터 1년으로 센다.
2. 계절 지수는 해당 라인의 실적 수량 중 같은 달 평균 ÷ 전체 관측 월 평균이다. `seasonal=false`, 해당 달 관측 없음, 전체 평균 0이면 1을 쓴다. 월별 수량을 지정한 달에는 계절성과 성장률을 다시 곱하지 않는다.
3. 단가는 해당 월 지정값을 우선하고 생략한 달에는 기준 단가를 쓴다. 수량에는 라인 배수, 단가에는 `price_multiplier`를 각각 곱한다. 두 적용값의 곱을 표시 단위로 환산한 뒤 월 가산액과 확장 조정을 더한다.

### 활동량 기준 매출

실적 월마다 `sales_volume.csv`에 활동량, 판매 수량, 개당 원 단가를 적는다. 실적 활동당 수량은 판매 수량 ÷ 활동량이다. 활동량과 수량이 모두 0이면 활동당 수량도 0이다. 연간 활동량·수량·매출은 월 합계, 연간 활동당 수량은 합계 수량 ÷ 합계 활동량, 연간 단가는 합계 활동 기준 매출(원) ÷ 합계 수량이다.

각 요소의 `base`와 추정 월별 입력 `monthly`는 독립적으로 정한다. 아래는 계획 연도가 2027년인 매출 라인의 예다.

```json
{"id":"A","label":"제품 A","accounts":["제품 A 매출"],"driver":"activity",
 "params":{"activity":{"base":"last_12m"},
           "yield":{"base":"seasonal_avg","start":"2025-01","end":"2026-12"},
           "yield_growth":0.02,
           "price":{"base":"base_month","month":"2026-12","seasonal":false},
           "price_steps":[{"month":"2026-10","pct":0.10,"basis":"10월 단가표",
                           "apply_to":"pre_step_months"}]},
 "basis":"월별 활동·판매 기록과 변경 단가표"}
```

| 기준 | 추정 월에 적용할 값 |
|---|---|
| `last_12m` | 실적 마감까지 최근 12개월 중 같은 달의 관측값. 세 요소의 기본값이다. |
| `seasonal_avg` | `start`~`end` 실적 중 같은 달 관측값의 평균. 기간 평균 × 해당 달 계절지수와 같다. 기간을 생략하면 전 실적을 쓴다. |
| `manual` | 각 추정 월에 해당 요소의 `monthly` 값 또는 계획 CSV 행을 제공한다. 예컨대 `"activity":{"base":"manual","monthly":{"2027-01":120}}`은 1월 활동 120회를 지정한다. |
| `base_month` | 단가 전용. `month`에 지정한 실적 월의 수준을 쓴다. `seasonal:true`이면 여기에 기간 내 해당 달 평균 단가 ÷ 기준 월과 같은 달의 평균 단가를 곱한다. |

`monthly`의 숫자 0도 지정값이다. 추정 월의 CSV 행은 활동량·활동당 수량(수량 ÷ 활동량)·단가를 한꺼번에 지정한다. 같은 요소·월을 설계서와 CSV 양쪽에 적으면 값이 일치해야 한다. `yield_growth`는 월별 지정값을 포함한 기준 활동당 수량에 적용한다. 실적 마감 연도 수준을 기준으로 이후 매년 1월에 한 번 복리로 반영한다.

특정 활동군의 월 계획을 한 곳에서 조정하려면 활동 매출의 `params.increment`를 사용한다. 예를 들어 `{"label":"추가 서비스 월 운영 횟수","monthly":{"2027-03":20},"included_monthly":{"2027-03":12},"whole":true,"yield_per_activity":8,"metric_factors":{"work":15}}`는 기존 기준에 포함된 12회를 빼고 8회·64개·작업량 120을 더한다. 입력을 5회로 줄이면 7회·56개·작업량 105를 차감한다. `included_monthly`의 생략 월은 0이고 `monthly`의 생략 월은 해당 월 포함 횟수를 초기값으로 쓴다. 생성된 상세 시트 27행은 0 이상 월 계획 입력이며 28행은 이미 포함된 횟수다. `whole:true`이면 정수만 허용한다. 수량·지표의 기준 계수와 추가분 계수는 활동량으로 가중한다. 별도로 지정하지 않은 지표에는 기존 계수를 적용한다. 시나리오의 활동량·활동당 수량·단가 배수 및 영업계획은 이 기준을 만든 다음 적용한다.

`fixed_inflation.params.activity_increment`에 `{"line":"A","unit_cost":1200.123}`처럼 활동 매출 ID와 회당 원가(원)를 지정하면 상세 시트에서 계산한 월 순증감 횟수 × 회당 원가를 원 단위로 반올림해 인상 전 비용으로 쓴다. 기초 활동에 대한 기존 비용은 원래 라인에 남으며, 감축으로 생긴 차액은 연결한 라인에 음수로 표시한다. 직군별 인상과 소급 정산에도 같은 기준을 적용한다. 이 방식에서는 독립적인 `monthly` 비용이나 0 이외의 `base_monthly`를 함께 지정할 수 없다.

`price_steps`의 각 행은 시행 월 `month`, 변화율 `pct`(10%는 0.10), 근거 `basis`를 함께 지정한다. 여러 건은 적용되는 인상 배수를 곱한다. 기본 `apply_to:"all"`은 시행 월 이후의 모든 추정 기준 단가에 인상률을 적용한다. `"pre_step_months"`는 실적에 이미 포함된 인상의 경우 시행 전 관측치만 환산한 뒤 기준값을 산출한다. 추정 중 시행하는 인상은 그달부터 실적 유래 기준 단가에 적용한다. 이 옵션에서 직접 지정한 추정 월 단가는 그달의 인상을 반영한 최종 수준으로 본다. 어느 경우든 실적 월에는 관측 단가를 표시한다.

### 사업부 계획과 연동 비용

`metrics`, `initiatives`, `initiative_blank_rows`는 설계서 최상위 필드다. 아래 예는 앞 절의 활동 매출 A와 비용 라인 `usage`가 있을 때 넣는 설정이다.

```json
{
  "metrics":[{"id":"work","label":"작업량","lines":{"A":{"base":"actual"}}}],
  "initiatives":[{"id":"add","name":"A 추가 운영","line":"A","enabled":true,
                  "start":"2027-03","end":"2027-09","activity_delta":4,
                  "metric_factors":{"work":25},"cost_line":"usage","fixed_cost":12000}],
  "initiative_blank_rows":10,
  "scenarios":{"Base":{"initiatives":["add"]},"Down":{"initiatives":[]}}
}
```

| 계획 입력 | 적용 방법 |
|---|---|
| `id`, `name`, `line`, `start` | 고유 계획 ID, 화면 표시명, 대상 활동 매출 ID, 시작 추정 월. 모두 필수다. |
| `enabled`, `end` | 전 케이스 공통 스위치(기본 true). 시작·종료 월을 모두 포함한다. 종료 월을 생략하면 계획 끝까지 적용한다. |
| `activity_delta`, `yield`, `price` | 부호 있는 월 활동량 증감(기본 0). 증감 활동에 한정해 활동당 수량·개당 원 단가를 지정할 수 있다. 비우면 그 행 적용 직전의 라인 평균을 쓴다. 기준이 되는 물량이 0이면 계획 조정 전 값을 쓴다. |
| `yield_pct`, `price_pct` | 활동 증감을 반영한 뒤 라인 전체 활동당 수량과 단가에 각각 적용하는 변화율. 기본 0이고 최솟값은 −1이다. |
| `metric_factors` | 해당 라인에 연결된 지표 ID별 계수. `{"work":25}`는 이 계획으로 증감하는 활동 1회당 작업량 25를 적용한다. 생략하면 해당 월 라인 계수를 쓴다. |
| `fixed_cost`, `cost_line` | 활동 증감과 별개로 적용 기간마다 더할 비용(원). 감소는 음수다. 금액을 주면 대상 비용 ID도 적는다. 투자 모듈 전용 감가상각 라인은 대상에서 제외된다. |

`영업계획`의 입력 행을 위에서 아래로 적용한다. 같은 라인에서 두 변화율이 겹치면 순차로 곱하고, 각 행의 직전·직후 차이를 그 계획에 배정한다. `민감도및결과`의 계획 종료 연도 표에는 선택 케이스의 계획별 매출 증감, 연동 원가 증감, 공헌이익 증감(매출 증감 − 연동 원가 증감)이 표시 단위로 나타난다.

`scenarios.Base/Up/Down.initiatives`에는 적용할 ID 배열을 적는다. 생략하면 등록 계획 전체, 빈 배열이면 어느 등록 계획도 선택하지 않는다. `cases[].initiatives`는 기준 시나리오의 목록을 대체한다. 생략하면 기준 시나리오 목록을 따른다. 해당 월의 계획이 적용되려면 `영업계획`의 공통 스위치와 `Sensitivity`의 케이스별 스위치가 모두 1이어야 한다. `initiative_blank_rows`는 추가로 준비할 빈 행 수(기본 10, 0 허용)다. 빈 행에 이름, 대상 ID, 적용 1, 시작 월과 변경 내역을 적으면 계산된다. 새 행의 케이스별 스위치는 처음에 모두 1이다.

`metrics[].lines`에는 지표에 포함할 활동 매출 ID와 그 계수를 적는다. `{"A":20,"B":{"base":"actual","monthly":{"2027-03":22}}}`의 A는 상수 20, B는 실적 지표 ÷ 실적 활동량을 구해 최근 12개월의 같은 달 계수를 쓰며 3월 계획은 22로 지정한다. 상수를 사용해도 실적 CSV 관측값이 있으면 해당 월 지표는 관측값을 표시한다. 계획 지표는 각 라인의 기준 활동량 × 계수와 계획별 지표 증감을 모두 더한다.

`per_metric`과 `per_activity`의 `unit_cost:"actual"`은 실적 마감까지 최근 최대 12개월의 비용 합계(원) ÷ 같은 기간 물량 합계다. 분모가 양수여야 한다. 원가를 직접 주면 0 이상 숫자를 쓴다. `per_metric`에는 월별 단위원가 객체도 지정할 수 있다. 해당 단위원가에 연 증감률을 반영하고, 산출한 월 비용에 일반 비용 라인 배수를 적용한다. `consumption`은 월 사용량 = 지표 ÷ 효율, 변동비(원) = 사용량 × (구매 단가 − 단위 보조)다. 변동비에 추정 월의 `adjustments`(부호 있는 원 금액)를 더한 뒤 일반 라인 배수를 적용한다. 계획의 월 고정비는 대상 비용 라인에 별도로 한 번 더한다. `pct_of_revenue.params.base_lines`는 기존 `revenue_ids`와 같은 필드다. 둘 다 지정하면 대상 ID 집합이 같아야 한다.

### 월별 구매 단가·효율·보조와 단위원가

아래는 첫 추정 월이 2027년 1월인 `consumption` 비용의 `params` 예다. 실적 사용량은 지표와 별도로 수집한 구매·소모 단위의 물량이다.

```json
{"metric":"work","efficiency":4,
 "price":{"2027-01":1800,"2027-04":1850},"subsidy":{"2027-01":100,"2027-07":80},
 "actual_usage":{"2026-12":350},"adjustments":{"2027-02":12000}}
```

- 숫자 하나를 주면 `활동지표`의 모든 추정 월 입력 칸이 그 기준 셀을 참조한다. 어느 한 달에 다른 값을 직접 쓰면 그달의 기준이 바뀐다.
- 월별 객체에는 첫 추정 월을 반드시 적는다. 생성할 때 다음 변경 월 전까지 마지막 지정값을 채운다. 위 단가는 1~3월 1,800원, 4월부터 1,850원이다. 생성 후 월별 노란 칸은 각각 편집한다. 효율은 양수, 단가·보조는 0 이상이다. 보정액과 배당 등 일반 월별 금액표는 지정 월에만 반영되고 미지정 월은 0이다.
- 계정의 실적 비용(원) ÷ 양의 관측 사용량을 실적 월의 구매 단가 행에 참고로 표시한다. 사용량이 누락되거나 0이면 단가를 비운다. 계정에 보조·정산액이 포함되면 표시 단가도 그 효과를 포함한 비용 단가다.
- `전제사항`의 시나리오 구역에서 `consumption` 비용 라인별 효율·구매 단가·단위 보조 배수를 정한다. `Sensitivity`의 ‘구매 단가 배수 직접 입력’에서 Base·Up·Down 또는 추가 케이스에 숫자를 적으면 그 케이스의 최종 구매 단가 배수로 사용한다. 빈 칸은 선택한 시나리오의 배수를 따른다. 예를 들어 월 입력 단가 1,800원과 케이스 단가 배수 1.05이면 해당 케이스 구매 단가는 1,890원이다.
- `per_metric.params.unit_cost`에 `{"2027-01":5,"2027-06":5.5}`처럼 변경 월을 적거나, 숫자 또는 `"actual"`을 준다. 후자의 월 칸은 최근 최대 12개월 실적 가중단가 셀을 참조한다. 월 칸에 기준 원가를 직접 입력한 후에도 `annual_growth`와 비용 라인 배수가 적용된다. `per_activity`는 숫자 또는 `"actual"`을 사용한다.

#### 구매 단가 연동 보조

`consumption.params.subsidy_link`는 구매 단가에 따라 달라지는 보조액을 추정 월마다 계산한다. 월별 `subsidy`에는 실적 기준 단위당 보조금 전체를 적고, `baseline_amount`에는 그 금액에 이미 포함된 기준 연동 보조액을 적는다. 기준 연동 보조액은 실적 구매 단가와 당시 연동률로 계산한 단위당 연동액에 지원 대상 비율을 곱한 금액이다.

| 필드 | 단위 및 입력 기준 |
| --- | --- |
| `threshold` | 원/사용단위. 초과분에 보조가 적용되는 기준 구매 단가, 0 이상 |
| `rate` | 초과분에 적용하는 기본 연동률, 0~1 |
| `cap` | 원/사용단위. 지원 대상 비율을 곱하기 전의 단위당 연동 한도, 0 이상 |
| `eligible_share` | 지원 대상 사용량 ÷ 전체 사용량, 0~1 |
| `baseline_amount` | 원/사용단위. 실적 보조금에 포함된 기준 연동액, 0 이상 |
| `annual_rates` | 선택. 달력 연도별 연동률. `{"2027":0.3}`이면 2027년에만 30%를 쓰며, 다른 연도에는 `rate`를 쓴다. |
| `basis` | 선택. 지원 조건·계산 자료의 출처. 생략하면 비용 라인의 `basis`를 표시한다. |

적용 구매 단가 `P`는 월별 `price`에 해당 케이스의 구매 단가 배수를 곱한 값이다. 적용 단위 보조금은 `(월별 subsidy + eligible_share × MIN(MAX(P − threshold, 0) × 해당 연도 연동률, cap) − baseline_amount) × subsidy_multiplier`다. `전제사항`의 비용 라인에서 연동 조건을 편집하고, `활동지표`의 ‘적용 단위 보조 (원/단위)’에서 월별 결과를 확인한다.

예를 들어 기준 단가 100원, 연동률 40%, 한도 30원, 대상 비율 80%, 기준 연동액 8원, 월별 기준 보조금 18원으로 설정하고 단위 보조 배수를 1로 두면, 적용 구매 단가가 90원·125원·200원일 때 단위 보조금은 각각 10원·18원·34원이다. 구매 단가 배수로 125원이 150원이 되면 보조금은 26원이다.

### 준변동비와 비용 간 연동

```json
[
  {"id":"power","label":"전력비","accounts":["전력비"],"section":"매출원가","method":"mixed",
   "params":{"base_monthly":300000,"annual_growth":0.03,"revenue_ids":["kits"],"rate":0.02},
   "basis":"기본요금과 제품 생산에 연동되는 전력 사용분"},
  {"id":"bonus","label":"상여","accounts":["상여"],"section":"판관비","method":"pct_of_line",
   "params":{"line_ids":["salaries"],"rate":0.08},"basis":"등록된 급여 비용 라인의 8%"}
]
```

준변동비는 기준 월 고정분 × (1 + 연 인상률)의 경과 연도 수 제곱 + 대상 매출 합계 × 비율이다. `pct_of_line`은 등록된 매출 또는 비용 라인의 **해당 월 최종 금액**을 합해 비율을 곱한다. 위 예에서는 설계서에 `salaries` 비용 라인도 있어야 한다. 두 방식 모두 산출한 비용에 자기 라인의 케이스 배수·월 가산액·확장 조정이 적용된다. 자기 자신 또는 여러 비용 라인을 거쳐 돌아오는 참조는 검증 오류다.

비용의 `pct_of_line`, `mixed`, `fixed_inflation`은 `params.months`에 적용할 달 번호를 지정할 수 있다. 예컨대 급여 연동 상여의 `{"line_ids":["salaries"],"rate":1,"months":[6,12]}`는 6월과 12월에만 해당 월 급여를 기준으로 계산한다. 생략하면 모든 달에 적용한다. 실적 손익은 원천 자료대로 읽는다.

`fixed_inflation` 또는 `mixed` 비용 라인에서 `follows_wage_raise:true`를 **라인 최상위**에 지정하면 고정분은 공통 임금 인상률을 따르고, `params.role`에 등록 직군을 지정하면 해당 직군의 인상률과 시행 월을 따른다. 변동분은 지정 매출과 비율로 계산한다. 공통 임금 인상률은 인원 또는 이 설정을 통해 실제 수식에서 사용할 때 전제사항에 표시한다.

### 직군별 임금 인상과 기대 인원

직군의 `count`에는 0 이상의 기대 인원(예시 1.5명)을 넣을 수 있다. `wages.roles[].annual_raise`가 있으면 그 직군 인상률, 생략하면 `wages.annual_raise`를 쓴다. 최초 인상 월부터 적용하고 이후 12개월마다 한 번 더 적용한다. 소급 협약을 지정하지 않은 경우의 시행 규칙은 다음과 같다. 기존 직군의 기본 최초 인상 월은 실적 마감 다음 해 1월, 추정 기간에 채용하는 직군은 입사 다음 해 1월이다. `raise_from`으로 최초 월을 지정할 수 있다. 예를 들어 2027-04 입사, 기준 월급 250만원, 인상률 4%인 직군은 기본 설정에서 2027년 250만원, 2028년 1월부터 260만원이다. `raise_from="2028-04"`이면 260만원을 처음 적용하는 달이 2028년 4월이다. 신규 직군에 자체 `annual_raise`를 지정하면 소급 협약 없이도 입사 월부터 명시적 `raise_from`을 줄 수 있다. 예를 들어 2027년 4월 입사 직군에 `annual_raise:0.04`, `raise_from:"2027-07"`을 함께 주면 7월부터 260만원이다. 공통 인상률만 쓰는 신규 직군은 기존 규칙에 따라 입사 다음 해 1월부터 인상 월을 정한다. 입사 전 월은 최초 인상 월이 될 수 없다.

`per_headcount.params.monthly_cost`를 명시하면 그 단가에 **각 직군의** 인원과 인상 배수를 곱해 합산한다. 같은 이름의 여러 채용 집단도 시작 월에 따라 인상 시점이 다를 수 있다. 단가 생략 시 해당 직군의 인건비 합계를 사용한다. `headcount.csv`를 제공할 때 설계서의 `wages.roles[].raise_from`과 `annual_raise`로 직군 조건을 보완할 수 있다. 직군명과 설계서에 적은 시작·종료 월로 CSV 한 행이 식별되어야 한다. CSV에도 `raise_from`을 적으면 설계서 값과 같아야 한다.

### 소급 협약의 손익·현금 인식

```json
{"wages":{"annual_raise":0.04,
          "roles":[{"role":"운영","annual_raise":0.045},{"role":"지원"}],
          "retro":{"effective_from":"2027-02","settled":"2027-09","recognition":"accrual"}}}
```

위 예는 기존 직군의 기준 급여에 2월부터 운영 4.5%, 지원 4.0%를 적용하고 9월에 소급분을 지급한다. 직군별 기준 급여와 인원은 같은 설계서의 직군 행 또는 `headcount.csv`에 넣는다. `effective_from`은 추정 기간 안에서, `settled`는 적용 월과 같거나 그 이후로 정한다. 정산이 계획 종료 이후이면 소급분의 일괄 지급은 계획 기간 밖에 있다. `accrual`이면 기간 중 인상분을 손익에 인식하고 마지막 계획 월에 미지급비용이 남는다. `lump`이면 그 소급분의 손익 인식과 지급이 모두 정산 월로 넘어가고 계획 말 미지급비용은 0이다.

| `recognition` | 시행 월부터 정산 전까지 | 정산 월 |
|---|---|---|
| `accrual` | 인상분을 매월 손익에 인식하고 지급 대상 인상분을 미지급비용에 누적 | 당월 인상 급여와 이전 월 소급분을 지급하고 미지급 잔액을 해소 |
| `lump` | 인상 전 금액만 손익과 현금에 반영 | 이전 월 인상분을 당월 손익에 한 번 더해 지급 |

`전제사항` 인건비 구역에서 협약 월과 인식 방식을 편집한다(0 발생, 1 정산 월 일시 인식). `인건비`에서 급여 라인별 소급 대상 금액·정산 누계와 미지급 기말 잔액을 확인한다. 비현금 비용은 소급 손익 시점 조정에는 포함되지만 현금 지급용 미지급에는 포함하지 않는다. BS를 만들면 미지급비용을 `BS명세`에 별도로 표시한다.

기존 인원과 협약 시행 전 채용 인원의 첫 인상 월은 기본적으로 `effective_from`이다. 시행 월 이후(당월 포함)에 입사하면 입사 급여가 이미 협약 수준이라고 보고 최초 인상을 입사 다음 해 1월로 둔다. 직군의 `raise_from`을 명시하면 협약 시행 월 이후가 되어야 하며, 추정 중 입사한 인원은 입사 월보다 앞당길 수 없다.

계정 기준 급여에도 같은 정책을 적용할 수 있다. 예를 들어 비용 라인 최상위에 `"method":"fixed_inflation","follows_wage_raise":true`, `params`에 `{"base_monthly":2000000,"role":"운영"}`을 적는다. `headcount.csv` 없이 계정 기준 고정비만 계획하는 경우 `wages.roles`에 `{"role":"운영","annual_raise":0.045}`만 등록해도 된다. 이때 인상률을 비용의 기준 월액에 적용하고, 생략된 인원·1인당 비용은 0이다. 같은 이름의 여러 직군 행을 이 고정비에 연결할 때는 적용 인상률과 최초 인상 월을 일치시킨다. 모델 생성 후 일부 행만 바꾸면 월별 정책 일치 검사를 확인한다. `role`을 생략하면 공통 인상률과 협약 시행 월을 따른다. `mixed`에서 같은 설정은 고정분에만 적용한다. `params.months`가 있으면 대상 월에 발생한 인상분만 쌓아 정산 월에 지급한다.

소급분은 별도의 미지급·지급 스케줄로 처리한다. 일반 매출원가를 쓰는 재고·매입채무 회전 기준에서는 발생 방식의 정산 전 소급 인상분, 일시 방식의 정산 월 일괄 인상분을 빼서 회전일수로 현금 지급을 한 번 더 이연하는 일을 막는다. `dio_base_lines` 또는 `dpo_base_lines`를 지정한 경우에는 그 대상 비용 라인에 포함된 소급분만 차감한다. 정산 월 이후의 정규 급여 인상분은 지정된 운전자본 기준에 계속 포함한다.

### 영업외손익과 비현금 비용

`non_operating.income_monthly`와 `non_operating.other_expense_monthly`는 추정 영업외수익과 이자 **외** 영업외비용이다. 원 단위 월액 하나를 적으면 모든 추정 월에 적용하고 월별 객체를 적으면 지정 월만 적용한다. 예를 들어 `{"income_monthly":50000,"other_expense_monthly":{"2027-03":120000},"basis":"예금이자와 3월 처분손실 계획"}`이면 매월 영업외수익 5만원, 3월 기타 영업외비용 12만원이다. 엑셀에서는 전제사항의 법인세 구역에서 일정 월액은 G열, 월별 계획은 K열부터 표시 단위로 입력한다. 약정 이자는 재원조달에서 별도로 더한다. IS 본표의 `영업외수익`과 상세행 `영업외수익 세부 내역`은 매월 같은 금액이다.

생략한 필드의 추정값은 0이다. 해당 실적 총액이 0이 아니면 실적 합계 ÷ 전체 실적 월 수를 경고에 표시한다. 기타 비용 평균에서는 엔진이 이자로 식별한 계정(이자비용, 지급이자, interestexpense, interest)을 뺀다. 0을 명시하거나 월별 객체에 특정 월만 넣은 경우는 사용자가 정한 가정으로 처리한다.

`cost_lines[].noncash`는 기본 false다. 예를 들어 퇴직급여충당부채 전입을 별도 비용 라인에 배정하고 true로 지정하면 추정 손익에는 비용, CF에는 같은 금액의 가산, BS가 있으면 BS명세의 기타 비유동부채에는 전월 잔액에 당월 전입을 더한 금액이 표시된다. 비현금 가산은 EBITDA 산식에 들어가지 않는다. 상각 전용 라인은 투자비에서 이미 CF에 가산되므로 noncash=true로 중복 지정하면 오류다.

### 운전자본 회전일수와 매입채무 산정

월말 잔액과 같은 달의 흐름을 쓴다. 일수는 `working_capital.day_basis`에 따라 해당 달의 달력 일수 또는 30일이며 기초·기말 평균 잔액을 쓰지 않는다. 분자와 분모의 금액 단위를 맞추면 원이나 표시 단위 어느 쪽으로도 같은 일수가 나온다.

| 지표 | 실적에서 일수를 구하는 식 | 추정 월말 잔액 |
|---|---|---|
| DSO | 월말 매출채권 ÷ 당월 채권 대상 매출 × 월 일수 | max(0, 채권 대상 매출) × dso ÷ 월 일수 |
| DIO | 월말 재고자산 ÷ 당월 기준 원가 × 월 일수 | max(0, 기준 원가) × dio ÷ 월 일수 |
| DPO | 월말 매입채무 ÷ 당월 선택 기준액 × 월 일수 | max(0, 선택 기준액) × dpo ÷ 월 일수 |

당월에 즉시 입금되는 매출이 있으면 `working_capital.cash_revenue_lines`에 해당 매출 라인 ID를 적는다. 매출채권의 회전 기준액은 총매출에서 지정한 라인의 당월 매출을 뺀 금액이다. 지정 목록은 중복 없는 비어 있지 않은 배열이며, 생략하면 총매출 기준을 적용한다. 실적 월말 잔액과 매출채권 마감 월 대사도 같은 기준을 따른다.

기준 라인 목록이 없으면 재고의 기준액은 상각비·비현금 비용을 포함한 손익의 매출원가 전체다. 매입채무의 기본 기준액은 매출원가 전체에 재고 증감을 더한 매입액이다. `working_capital.ap_base="purchases"`(기본)는 매출원가 + 당월말 재고 − 전월말 재고, `"cogs"`는 매출원가를 쓴다. 예컨대 30일인 달에 원가 90, 재고 증가 15, DPO 20일이면 매입채무는 각각 70과 60이다. 마감 월 매입액을 구할 때는 실적 BS에서 전월말 재고를 가져온다. 실적 BS가 있으면 설계서의 DSO·DIO·DPO와 동일 기준으로 마감 월 채권·재고·채무를 역산해 원천 잔액과 대조한다. 차이가 5%를 넘는 항목은 설계서 검증 경고에서 확인한다. 분모가 0이거나 원천 잔액이 없어 일수를 직접 계산할 수 없으면 근거를 기록한다.

회사 원가 구조가 다르면 `working_capital.dio_base_lines`(재고)와 `working_capital.dpo_base_lines`(매입채무)를 **각각** 지정한다. 값은 등록된 비용 라인 ID의 비어 있지 않은 배열이며 같은 배열 안의 ID는 중복될 수 없다. 두 목록에 같은 라인을 쓰는 것은 가능하다. 지정한 지표의 기준액은 해당 비용 라인 금액의 직접 합계다. DPO 목록을 지정하면 `ap_base`보다 목록이 우선하며 재고 증감을 더하지 않는다. 목록을 생략한 지표에는 기존 기준을 적용한다. 실적 마감 월은 각 라인의 `section, accounts`에 배정된 원천 계정 금액, 추정 월은 같은 비용 라인의 추정 금액을 합산한다. 예를 들어 재고의 기준을 상각 제외 원가로 잡으면 해당 원가 라인들만 DIO 목록에 적고, 매입채무가 재료비·외주비·소모품비에 비례한다면 그 세 비용 라인 ID를 DPO 목록에 적는다. 마감 월 잔액 대조에도 같은 기준을 사용하며, 차이가 **5%를 초과**하면 경고한다.

BS가 있으면 실적 월 잔액을 사용한다. BS 생략 시 마감 현금은 `financing.opening_cash`, 마감 운전자본은 마감 월 매출·해당 지표의 기준액과 회전일수로 추정한다. 기준 라인 미지정 시 전월 재고 자료가 없는 마감 월 매입액은 원가와 같다. 추정 월의 운전자본 현금효과는 전월 채권 − 당월 채권 + 전월 재고 − 당월 재고 + 당월 채무 − 전월 채무다.

민감도및결과의 연도 구분은 모델에 있는 월을 기준으로 정한다. 해당 월이 모두 마감 이내이면 실적, 마감 전후가 섞이면 예상, 모두 추정이면 계획이다. BS가 없는 회사의 전부 실적인 연도는 기말 현금, 최저 월말 현금과 그 발생 월, 기말 차입금에 ‘자료 없음’을 표시한다. 전부 실적인 연도의 ‘DSCR (계획 구간)’에는 ‘해당 없음’이 표시된다. 계획 종료가 연중이면 해당 연도의 전망은 종료 월까지의 합계다.

### 사업연도별 법인세 입력

법인세·지방세 세율표와 납부 일정의 기준일은 2026년 11월 24일, 이월세액공제·최저한세·농어촌특별세 조문의 확인일은 11월 26일이다. 사업연도 **개시일**로 적용 표를 고른다. 제공된 표는 2023년 이후 개시 사업연도부터 지원한다. 계획 연도의 개정 여부와 회사의 신고자료를 확인하고, 세무조정계산서·납부서·회사의 분납 계획에서 금액과 근거를 옮긴다. 세율과 한도표는 [대한민국 법인세 계산 기준](tax_rules_kr.md)을 따른다.

| 설계서 tax 필드 | 입력과 생략 처리 |
|---|---|
| `fy_start_month`, `short_fys`, `founded_fy` | 통상 개시 월은 1~12, 기본 1월. `short_fys`는 실제 단기 사업연도의 개시 월을 키, 종료 월(포함)을 값으로 하는 YYYY-MM 객체다. `founded_fy`는 신설 법인의 첫 사업연도 개시 월이다. 계획이 연중에 끝나더라도 그 사유로 단기 사업연도를 지정하지 않는다. |
| `sme` 또는 `is_sme`, `corporation_type`, `faithful_filing` | 중소기업 여부는 두 이름 중 하나로 입력한다. 둘 다 입력하면 값이 같아야 한다. 중소기업 여부가 없으면 확인 경고 후 비중소기업으로 계산한다. 법인 구분은 `general`(기본) 또는 `small_filing`. 성실신고확인서 실제 제출 여부는 별도 불리언이며 기본 false다. 각각 공제·예납·분납, 세율표, 확정 납부기한에 사용한다. |
| `rate_tables`, `include_local` | `pre2026`과 `from2026` 각각에 원 단위 과표 경계 세 개 `thresholds`, 구간별 세율 네 개씩 `national_general`, `national_small_filing`, `local_general`, `local_small_filing`을 둔다. 기본값은 기준서 §3·4다. 소규모 지방세율은 §4 본문에 따라 §3의 해당 국세율을 10분의 1로 계산한다. §4의 인쇄 표는 일반 법인의 지방세율이다. 소규모 특례 적용 전인 2025년 이전 개시 연도는 국세·지방세 모두 일반 표를 쓴다. 지방세 포함 기본 true. 전제사항에서 세율표를 편집할 수 있다. |
| `loss_vintages`, `loss_limit_override` | 발생 사업연도별 `{"fy_start":"YYYY-MM","amount":원금액}` 배열. 발생연도 미상은 `"unknown"`. 과거의 `loss_carryforward` 단일 잔액도 발생연도 미상으로 받아 만료를 판단할 수 없다는 경고를 낸다. 한도율 미지정 시 중소기업 100%, 그 외 80%. 별도 적용 근거가 있으면 `loss_limit_override`에 비율을 적는다. |
| `minimum_tax` | `apply`는 최저한세 적용 여부, `rate`는 `"auto"` 또는 0~1 사이의 율이다. 새 공제 계산을 사용하면 기본값은 true와 `"auto"`다. 자동이면 중소기업 7%, 그 밖의 법인은 구간별 10%·12%·17%다. 졸업 유예가 적용되면 해당 기간에 0.08 또는 0.09를 직접 지정한다. |
| `credit_vintages`, `credit_balance_as_of` | 신고서상 기초 미공제 잔액을 발생 사업연도·공제 유형별로 적는다. 각 행에 `year`(사업연도 개시연도), `label`, `amount`(원), `minimum_tax_applies`, `rural_tax`를 입력한다. 기초 잔액을 입력하면 기준 사업연도 종료 월 YYYY-MM도 지정한다. 해당 월은 실적 마감 이내여야 하며, 그 다음 월부터 손익 자료가 있어야 한다. |
| `new_credits` | 사업연도 개시연도별 신규 공제 발생액(원). 연도별 값은 숫자, 유형별 객체 하나 또는 객체 배열이다. 숫자는 최저한세 대상·농어촌특별세 비과세로 계산한다. 유형별 객체에는 `label`, `amount`, `minimum_tax_applies`, `rural_tax`를 지정한다. 객체에 `year`를 쓸 때는 연도 키와 맞춘다. 추정이 포함된 사업연도의 금액을 입력하며 생략하면 0이다. |
| `annual` | 실제 사업연도 개시 월 YYYY-MM별 객체. 연간 `additions` 익금산입·손금불산입, `deductions` 손금산입·익금불산입, `non_taxable` 비과세소득, `income_deduction` 소득공제, `credits` 감면·공제. 납부용 `withholding` 원천징수, `ad_hoc` 수시부과, `interim_paid` 마감일까지 실제 납부한 중간예납, `installment_amount` 확정 국세 중 회사가 분납할 금액. 각 금액은 원 단위이며 생략 시 0. |
| `prior` | 첫 추정 사업연도의 직전 사업연도 신고자료. `assessed_tax` 산출세액, `credits` 감면·공제, `withholding` 원천징수, `ad_hoc` 수시부과, `months` 실제 직전 사업연도 월수(등록된 직전 단기 사업연도면 그 월수, 통상 연도면 12), `is_sme` 직전 중소기업 여부(기본 현재 여부). 생략한 감면·기납부액은 0. 산출세액 미제공 시 직전 감면·기납부 자료가 일부 있어도 상반기 방식으로 계산한다. 유형별 공제를 사용하면 신고서의 산출세액이 명시적 0일 때도 상반기 방식을 쓴다. 실적 손익의 법인세 계정으로 직전 산출세액을 추정하지 않는다. |
| `opening` | 실적 마감 시점 국세·지방세 채무 `national_payable,local_payable`, 선납·환급 자산 `national_prepaid,local_prepaid`. 각 원 금액에 대해 **생략**은 원천 또는 추정 규칙을 적용하고 **명시적 0**은 회사가 확인한 0을 사용한다. |
| `paid_to_date.national, paid_to_date.local` | 실적 마감 사업연도에 마감일까지 실제 납부한 국세·지방세 **총액**(원). 세목별로 각각 선택 입력한다. 중간예납·원천징수 등 확인한 기납부가 이미 포함된 총액이므로 합산하지 않는다. 생략한 세목은 실적 인식액에서 해당 사업연도 미지급·선납 순잔액을 차감해 추정하고 확인된 기납부 증빙을 반영하며, 명시적 0은 해당 세목의 납부 총액 0이다. 총액은 기말 채무·선납 자산 잔액을 입력하는 `opening`과 별개다. |
| `installments` | 기본 false로 확정 국세를 일시 납부한다. true이면 회사가 제시한 해당 FY의 `annual[개시월].installment_amount`만 잔여 납부액 범위에서 이연한다. 분납할 금액이 미정이면 확인 경고를 남기고 미지정 이연액은 0으로 계산한다. |
| 옛 `rate` | 경고 후 계산에서 제외한다. 국세·지방세 모두 과표 구간별 한계세율을 사용한다. |

### 세액공제 잔액과 신규 발생액 입력 예시

계획 기간이 2028년까지인 12월 결산 중소기업의 2025년 말 신고 잔액과 2027년 신규 공제를 다음과 같이 입력한다. 2026년 10월 실적 마감이면 2026년 1월부터의 과표에 기초 잔액을 적용한다. 11월 추정 개시 시점에 2025년 말 잔액을 다시 투입하면 사용액이 중복된다.

```json
{
  "tax": {
    "sme": true,
    "minimum_tax": {"apply": true, "rate": "auto"},
    "credit_balance_as_of": "2025-12",
    "credit_vintages": [
      {"year": 2020, "label": "통합투자세액공제", "amount": 225112601, "minimum_tax_applies": true, "rural_tax": true}
    ],
    "new_credits": {
      "2027": [
        {"label": "통합투자세액공제", "amount": 30000000, "minimum_tax_applies": true, "rural_tax": true},
        {"label": "중소기업 사회보험료 세액공제", "amount": 10000000, "minimum_tax_applies": true, "rural_tax": false}
      ],
      "2028": 0
    }
  }
}
```

`year`와 `new_credits`의 연도 키는 개시연도를 뜻한다. 예를 들어 2026년 4월~2027년 3월 사업연도는 2026이다. 한 달력연도 안에 복수 사업연도가 개시되면 연도값만으로 구분할 수 없는 해당 입력을 거부한다. 이미 가진 공제의 기준일과 발생연도는 별도 정보다. 기초 잔액 없이 신규 발생액만 넣으면 첫 추정 월이 속한 사업연도의 직전 결산월을 기준으로 쓴다. 잔액 기준일 이후 전부 실적인 사업연도가 있으면 그 연도의 과세표준과 결손금 공제액을 신고서와 대조하거나, 최신 신고서와 대조한 결산월의 세액공제 잔액을 입력한다. 현재 결손금 잔액에는 과거에 사용한 결손금이 남아 있지 않기 때문이다.

`minimum_tax`, `credit_vintages`, `credit_balance_as_of`, `new_credits` 중 하나라도 입력하면 유형별 공제 계산을 사용한다. 이 필드를 모두 생략한 기존 설계서는 `annual.credits`를 기존 방식으로 반영한다. 두 방식을 함께 쓰면 유형별 공제를 먼저 적용한 후 남은 국세에서 `annual.credits`를 쓴다. 기존 필드의 공제는 당해 연도에만 쓰며 농어촌특별세와 최저한세 대상에서 제외한다. 같은 공제를 새 필드로 옮길 때는 기존 `annual.credits`에서 해당 금액을 빼고 두 플래그를 신고자료에 맞게 지정한다.

### 월별 손익과 이월결손금·세액공제

1. 사업연도 개시 월부터 당월까지 실적·추정 세전이익을 합산하고 세무조정을 더하고 뺀다. 연간 조정·비과세·소득공제와 해당 연도 신규 세액공제는 경과 월수 ÷ **실제 사업연도 월수**로 배분한다. 이월세액공제는 기초 잔액에서 사용 가능액을 계산한다.
2. 연도별 이월결손금은 공제 가능한 한도 내에서 오래된 것부터 쓴다. 기준서 §2에 따라 2020년 이전 개시 연도 발생분은 10년, 이후 발생분은 15년이다. 발생연도 미상은 만료 계산을 생략하며 알려진 기초 빈티지를 적용한 뒤 사용한다. 사업연도 종료 시 새 손실을 발생 연도별로 이월한다.
3. 사업연도 소득에서 결손금 공제·비과세소득·소득공제를 빼고 과세표준을 구한다. 누진 과표 구간별 국세를 합산한 뒤 감면·공제를 적용하고 지방세는 같은 과표에 해당 지방세율로 별도 계산한다. 실제 단기 사업연도면 과표 × 12 ÷ 사업연도 월수로 연환산하여 세율을 적용한 뒤 월수 ÷ 12를 곱한다.
4. IS의 ‘④ 기납부 차감 후 국세 납부할 세액’은 감면·공제 후 국세에서 해당 사업연도에 이미 납부한 중간예납·원천징수 등 인정 기납부를 뺀 금액을 보여 준다. 이 표시 행으로 당월 손익 법인세비용이나 CF를 다시 조정하지 않는다. 확정 납부 시점과 분납 이연은 CF 일정에서 확인한다.
5. 실적 법인세비용은 원천 계정을 그대로 쓴다. 추정 월 비용은 그달까지의 누적 국세 결정세액·법인지방소득세·농어촌특별세 합계에서 같은 사업연도의 전월까지 인식한 실제·추정 비용을 뺀다. 따라서 중간 마감 사업연도에는 실적분이 중복되지 않고 당월 비용이 음수일 수 있다. 연도별 결과표에는 과세표준, 법인세비용, 실효세율, 기말 이월결손금이 표시된다. 유형별 공제 사용 시 연도별 세액공제 사용액과 기말 이월세액공제도 확인한다.
6. IS에서 최저한세액, 대상 공제의 사용 한도, 공제 사용액, 국세 결정세액, 농어촌특별세를 확인한다. 이월결손금 등을 공제한 과세표준으로 계산한 국세 산출세액에 최저한세 한도를 적용한다. 한도 대상 공제를 먼저, 대상 밖 공제를 남은 국세 범위에서 쓴다. 각 그룹 안에서는 이월분, 먼저 발생한 연도, 동일 연도 입력 순서를 따른다. `rural_tax`가 true인 행의 사용액에 20%를 곱한다. 국세 공제는 별도로 계산하는 지방소득세에 영향을 주지 않는다.
7. 검증표에서 누진 세액·공제·최저한세·농어촌특별세 재계산, 월 비용 합계와 사업연도 부담액, 미지급세금·선납 잔액의 월별 연결을 점검한다. 이월세액공제 잔액표의 발생연도·유형별 기초 + 발생 − 사용 − 소멸 = 기말을 확인한다. 이월결손금은 별도의 `loss_vintages` 표에서 연결한다. 제132조 제1항 제2호의 과표 복원, 이연법인세 등 범위는 기준서 §8에 따른다.

### 법인세 납부와 마감 잔액

- BS에 국세·지방세·선납 잔액이 구분되면 각각 연결한다. ‘미지급법인세’처럼 구분 없는 기초 채무는 국세로 배정한다. BS가 없고 마감이 사업연도 중간이며 명시적 기초 잔액도 없으면, 해당 사업연도의 실적 누계 법인세비용에서 확인한 중간예납·원천징수 등 기납부액을 고려해 미납액을 추정한다. 음수 순액은 선납·환급으로 구분한다. 이 추정은 확인 필요 경고에 표시된다. 회사가 확인한 국세·지방세 구분 잔액을 `opening`에 입력해 추정치를 대체할 수 있다.
- `opening.national_payable`을 직접 입력하면 법인세와 농어촌특별세를 포함한 미지급 총액을 쓴다. 실적 BS에 농어촌특별세가 따로 있으면 그 잔액을 사용한다. 합계만 있으면 모델 누적 농어촌특별세, 실적 인식액, 남은 미지급액 범위에서 세목을 배분한다. 연중 마감 후 첫 추정 월은 같은 사업연도의 농어촌특별세 누적액과 기인식액 차이를 반영한다. `paid_to_date.national`은 이 사업연도의 국세 기납부액이다.
- 마감 전에 사업연도가 종료되었고 납부기한이 남으면 그 국세·지방세 기초 채무를 각각 다음 기한에 낸다. 실적과 추정이 섞인 사업연도는 사업연도 전체 확정 세액에서 기납부를 차감한다. 같은 세액에 속하는 기초 채무를 별도로 한 번 더 납부하지 않는다.
- 실적 마감 시점의 국세·지방세 미지급 잔액이 확인된 0이고 직전 사업연도 손익에 법인세비용이 있었다면 설계서 경고를 확인한다. 이미 납부한 것인지 장부에 채무가 누락된 것인지 회사에 묻는다. 출처가 없는 잔액은 확인된 0으로 간주하지 않는다.
- 직전 산출세액이 있는 첫 중간예납은 (산출세액 − 감면 − 원천징수 − 수시부과) × 6 ÷ 직전 월수로 계산한다. 사용자에게 직전 사업연도 법인세 신고서의 산출세액을 확인한다. 유형별 공제 계산은 직전 신고 산출세액 또는 모델이 추정한 직전 사업연도 산출세액이 0이면 상반기 방식을 적용한다. 새 공제 필드를 모두 생략한 기존 설계서에서 직전 산출세액 0은 종전처럼 직전 기준 방식으로 계산한다. 직전 신고 산출세액이 미제공이거나 상반기 방식이 적용되면 상반기를 하나의 사업연도로 보고 **상반기 누적 과표 × 12 ÷ 6**에 적용 국세 누진표를 먼저 적용한 뒤, 산출한 금액에 **6 ÷ 12**를 곱하고 상반기 사용 가능 공제를 차감한다. 두 방식 모두 농어촌특별세는 예납액에서 제외한다. 이후 모델 안에서 추정 결산을 마친 사업연도의 산출세액은 다음 해에 사용할 수 있다. 사업연도 8번째 월에 납부하며 직전 중소기업 계산액 50만원 미만, 6개월 이하 사업연도, 신설 법인의 첫 사업연도에는 예납 면제를 반영한다.
- 국세 확정 납부는 종료 월 +3개월, 지방세는 +4개월이다. 농어촌특별세는 국세 확정 신고 월에 일시 납부한다. 성실신고확인서를 제출하면 각각 한 달 늦어진다. 국세 납부액이 1천만원을 넘고 회사가 분납을 선택한 경우 지정 금액을 일반 법인 1개월, 중소기업 2개월 이내로 미룬다. 동일 FY의 기납부액·선납 자산은 한 번만 정산한다. 전부 추정인 사업연도에 원천징수·수시부과액의 연간 증빙만 있으면 연말에 현금 납부한 것으로 가정한다. 혼합 사업연도의 해당 입력은 마감일까지 실제 납부액이다. 기납부액이 당기 확정세액을 초과하면 해당 세목의 확정 신고 월에 초과분을 현금 환급으로 반영한다. 국세와 지방세는 각각 정산하며, 그 전까지의 초과분은 선납·환급 자산으로 표시한다. 납부 일정과 금액은 [법인세 계산 기준 §5](tax_rules_kr.md) 참조.
- CF 31~34행은 순서대로 기말 미지급법인세, 기말 선납·환급세액, 당월 순현금 납부액(납부액 − 환급액), 당월 손익 법인세비용이다. CF59·60행은 국세·지방세 환급액을 양수로 표시한다. 간접법 현금흐름은 CF13에 +CF34 − CF33을 반영한다. BS명세 16행 부채에는 CF31 증감, 11행 자산에는 CF32 증감을 반영한다. 실적 손익과 납부는 별개의 원천이다.

### 월별 취득 수량·가격과 자산군별 상각

```json
{"investment":{"dep_starts":"next_month","asset_classes":[
  {"asset_class":"장비 A","method":"straight_line","life_months":60,
   "purchases":[{"month":"2027-03","quantity":3,"unit_price":212000000}]},
  {"asset_class":"장비 B","method":"declining","life_months":48,"annual_rate":0.25,
   "opening":{"cost":40000000,"accumulated_dep":30000000,"remaining_life_months":8}}
]}}
```

`purchases`는 자산군·추정 월마다 한 건이다. `투자비`에서 월별 취득 수량과 단가(원)를 수정할 수 있다. 위 A의 3월 취득 지출은 636,000,000원이며 `dep_starts:"next_month"`이면 4월부터 상각한다. 자산군별 취득액과 금액 직접 입력(`monthly_capex`)을 합산하므로 서로 다른 취득만 배정한다.

정액은 취득원가 ÷ 내용연수(개월), 정률은 해당 월 상각 대상 장부가액 × 연 상각률 ÷ 12로 계산하며 자산군 정률은 0 초과 1 이하의 `annual_rate`가 필요하다. 신규분은 취득 월별로 내용연수를 세고 마지막 상각 월에 남은 순액을 상각한다. 기존분은 마감 월의 취득원가·누계액·잔여 개월 수를 사용해 잔여기간 마지막 달에 남은 장부가를 상각한다. 순액 0 이후의 상각비는 0이다. 같은 유형에서 잔여기간이 크게 다르면 별도 자산군 ID(`asset_class`)로 나눈다.

BS를 사용하는 모델은 실적 마감 유형자산 순액에서 자산군 `opening` 순액 합계를 뺀 미배정 부분에만 `existing_monthly_dep`를 적용한다. BS가 없으면 `opening_net_assets`를 기초 순액으로 쓰고, 0 또는 생략 시 명시한 자산군의 기존 순액을 합산한다. 자산군별 개시 순액 합계는 기초 총액 이하여야 한다. 기존 총액 방식의 월 취득액·상각은 자산군 없이도 사용할 수 있다.

### 감가상각 계정 지정

`investment.depreciation_accounts`에 손익 CSV의 매출원가·판관비 상각 계정명을 그대로 적는다. 예를 들어 `["제조감가상각비", "무형자산상각비"]`로 지정한다. 양쪽 손익 구분에 같은 계정명이 있으면 한 번 적으며, 계정 배정과 구분별 금액은 각 비용 라인에서 유지한다. 신규 취득분은 `investment.dep_starts`에 따라 취득 다음 월(기본) 또는 취득 월부터 상각한다. 표준 상각 계정명이 실적에 있는데 지정을 빠뜨리거나 실제 비용에 없는 이름을 적으면 설계서 검증에서 멈춘다. 회사 고유 계정명도 자료를 확인해 직접 지정한다.

지정 계정은 다른 비용과 분리한 전용 `manual` 라인에 배정한다. 이 라인의 `params.monthly`는 생략하거나 비우거나 0으로 적는다. 시나리오·민감도 배수는 1, 가산액은 0이며 확장 조정 대상에서 제외한다. 독립적인 비용 추정이나 조정이 설정되면 오류로 처리한다.

실적 EBITDA에는 지정 계정의 실적을 가산한다. 추정 구간에서는 투자비의 월별 상각비를 전용 라인에 배분하며, 매출원가와 판매관리비는 각 라인의 금액을 한 번씩 포함한다. 배분율은 실적 마감 월까지 최근 12개월(자료가 짧으면 제공 기간)의 전용 라인별 상각액 비중이다. 기간 합계가 0이면 전용 라인에 균등 배분한다. 과거 상각 계정이 없으면 빈 배열을 사용하며, 신규 투자에서 발생한 상각비는 매출원가에 반영한다.

### 배당·납입자본과 기타 비영업 자산·부채

```json
{"equity":{"dividends":{"2027-03":3000000},"contributions":{"2027-06":5000000}},
 "other_items":[{"label":"대여금 회수","bs_account":"단기대여금","bs_section":"유동자산",
                 "month":"2027-05","amount":-1000000}]}
```

월과 금액은 추정 월과 원 단위 정수다. 계획 입력은 `CF`의 ‘계획 배당·자본·기타 현금흐름’ 구역 노란 칸에서 원으로 고친다. 미지정 월은 0이다. 배당은 지급액을 양수로 적고 재무활동 유출과 이익잉여금 감소로 반영한다. 납입자본은 증자 양수, 감자 음수로 적으며 같은 부호로 재무활동 현금과 납입자본이 변한다. 마감 BS에서 납입자본을 식별할 수 있으면 기초 납입자본에 월별 증자·감자액을 누적한 잔액이 어느 달에도 음수가 될 수 없다. 설계서와 Excel의 월별 검증이 이 한도를 확인한다. 이익잉여금은 결손으로 음수일 수 있다. 배당 월별 표가 있는 모델의 연도별 결과에는 ‘배당 지급액’이 양수로 표시된다. 실적 월의 계획 배당 현금액을 역산하지 않으므로 전부 실적인 연도는 ‘자료 없음’이다.

`other_items[].amount`는 BS 잔액의 증감이다. 자산이 100만원 감소하면 예시처럼 −1,000,000원을 써서 투자활동 현금 유입 100만원이 된다. 자산 증가는 투자활동 유출이다. 부채 증가는 재무활동 유입, 상환은 재무활동 유출이다. 계획 손익에는 이 자금 이동으로 수익이나 비용이 생기지 않는다. CF의 해당 소계와 최소 보유현금·신규 조달 필요액에 현금 효과가 이어진다.

`bs_account`는 원천 계정명을 그대로 쓴다. 실적 자료에서 구분이 유일하면 `bs_section`을 생략할 수 있고, 신규 계정 또는 여러 구분에 있는 이름에는 반드시 지정한다. 현금·매출채권·재고·유형자산·매입채무·차입·전용 세무 계정처럼 자체 계산식이 있는 계정은 별도의 기타 증감 대상에 넣을 수 없다. 동일 계정에 여러 사유를 적으면 월별로 합산하여 잔액에 반영한다. 일반 양수 잔액 계정의 계획 회수·상환 누계가 가용 잔액을 초과하면 오류다.

BS가 있으면 실적 마감 잔액을 기초로 기타 계정의 계획 기말 잔액을 구한다. 기타 증감 계획이 없는 계정은 기초 잔액을 이월하며, 세금·비현금 비용·임금 소급 등 자체 계획이 있는 항목은 해당 산식대로 움직인다. 배당·납입자본이 있으면 `BS명세`에서 이익잉여금·납입자본·기타 자본을 별도로 볼 수 있다. 마감 자료에 자본 합계만 있으면 식별되지 않은 납입자본과 이익잉여금 행은 ‘계획 증감 누계 (기초 미구분)’로 표시한다. 미구분 기초 자본은 기타 자본으로 이월하며, 식별되지 않은 기초 납입자본에 한도를 추정하지 않는다. BS를 생략한 모델도 CF와 조달 효과를 계산한다. 기존 잔액의 회수·상환 계획에는 마감 잔액을 확인할 수 있는 BS 원자료가 필요하다.

### 조달 및 만기 처리

`financing.revolver_limit`에는 **기존 인출 잔액을 포함한 한도대출 총 한도**를 원으로 적는다. 총 한도 1억원에 기존 한도 약정 잔액이 4천만원이고 추가 인출 잔액이 없으면 남은 인출 가능액은 6천만원이다. 설계서에는 1억원을 입력한다. 모델은 기존 약정 사용 잔액과 추가 사용 잔액을 차감해 인출 여력을 계산한다.

`financing.funding_enabled`의 기본값은 `true`다. 최소 보유현금이 부족하면 한도 내에서 먼저 인출하고 나머지를 신규 차입으로 조달한다. `false`이면 추가 인출과 신규 차입을 중지한다. 최소 보유현금 검사는 실제 부족액을 계속 표시한다.

`financing.maturity_treatment`의 기본값 `repay`는 약정 원금을 예정대로 상환하고 남은 잔액을 만기에 상환한다. `rollover`는 약정 상환 후의 만기 잔액을 같은 금리로 계속 보유한다. 새 만기를 정하지 않은 연장 잔액은 유동차입금으로 표시한다.

약정별 `at_maturity`를 지정하면 해당 약정에 우선 적용한다. 생략하면 전체 `financing.maturity_treatment`를 따른다. 두 방식 모두 월별 약정 상환원금을 먼저 반영하며, 남은 잔액에 대해서만 만기 선택이 작동한다. 예컨대 `debt.csv`의 `loan_a`만 연장하려면 다음처럼 기존 약정 ID에 정책을 추가한다.

```json
{"financing":{"maturity_treatment":"repay","facilities":[{"facility":"loan_a","at_maturity":"rollover"}]}}
```

debt CSV가 없는 약정은 이름, 대주, 유형, 만기까지 갖춘 객체를 적는다. 엑셀 전제사항의 약정별 만기값은 −1 전체 설정 따름, 0 상환, 1 연장이다. 전체 스위치와 다르게 처리할 약정만 지정한다.

각 매출·비용 라인, `wages`, `investment`, `working_capital`, `financing`, `tax`, 개별 시나리오와 추가 케이스에 `basis` 문자열을 적을 수 있다. 근거를 생략하거나 공백만 적으면 검증기가 해당 항목 이름을 경고하고 모델 생성을 계속한다. 설계서·CSV에는 원 금액을 넣는다. 엑셀의 월별 매출·비용 직접 금액에는 표시 단위를 사용한다. 개당·고객당 단가, 1인당 비용, 활동 원가의 월별 단가·보조·보정액, CF의 배당·자본·기타 계정 계획 입력은 시트의 원 단위 표기를 따른다.

## 시나리오, 민감도와 월별 조정

`scenarios`에는 `Base`, `Up`, `Down` 세 이름을 쓴다. 생략된 시나리오는 기본 가정으로 생성한다. `multipliers`의 각 값은 0 이상 배수, `additions`의 각 값은 **모든 추정 월에 동일하게 더할 부호 있는 원 금액 하나**다. 두 객체의 키는 매출 또는 비용 라인 ID다. 미지정 라인은 배수 1, 월 가산액 0이다.

```json
{
  "scenarios": {
    "Up": {"multipliers": {"kits": 1.1}},
    "Down": {"additions": {"rent": 100000}}
  },
  "cases": [
    {"label": "교육 수요 증가", "scenario": "Base", "additions": {"classes": 200000}}
  ],
  "extensions": [
    {"line_id": "projects", "label": "특별 구축 지원", "monthly": {"2027-06": 130000}}
  ]
}
```

수량×단가 방식의 배수는 적용 수량에 반영한다. 계약 방식의 배수는 확인 계약 기대 매출과 미식별 신규 매출에 적용하고, 월 가산액은 미식별 신규 매출에만 더한다. 확장 금액은 시나리오 적용 후 별도로 더한다.

`scenarios.<이름>.drivers.<라인ID>`는 라인 내부의 동인을 바꾼다. 추가 케이스는 자신이 가리키는 시나리오의 동인 스위치를 기본으로 쓴다. `consumption` 구매 단가는 `Sensitivity`의 케이스별 직접 입력이 우선한다. 추가 케이스의 일반 라인 배수는 시나리오 라인 배수와 곱하고 일반 월 가산액은 합산한다.

| 라인 유형 | 동인 스위치 | 적용 순서 |
|---|---|---|
| price_volume | `price_multiplier` 기본 1 | 월별 적용 단가에만 곱한다. 일반 라인 배수는 수량에 적용한다. |
| activity | `activity_multiplier`, `yield_multiplier`, `price_multiplier` 기본 1 | 일반 라인 배수와 활동량 배수는 기준 활동량에 곱한다. 활동당 수량과 단가에는 각각의 배수를 곱한 뒤 사업부 계획을 적용한다. |
| consumption | `efficiency_multiplier`, `price_multiplier`, `subsidy_multiplier` 기본 1 | 효율, 구매 단가, 단위 보조에 각각 곱한다. 효율 배수는 양수다. |
| contracts | `new_multiplier` 기본 1, `exclude_unconfirmed` 기본 false | 계약별 월액 × 확률을 합산한다. `exclude_items`는 해당 라인의 미확정 계약 item 목록(기본 빈 배열)이다. 선택 항목의 현재 확률이 1 미만이면 그 계약만 0이 되고 확정 계약과 다른 항목은 유지된다. 제외가 true이면 확률 1 미만 계약의 기여가 0이다. 신규 월액에만 신규 배수를 곱한다. 갱신을 설정한 라인은 선택 필드 `renewal_probability`로 기본 갱신 확률을 대체할 수 있다. 계약 기대 매출과 신규 월액에 일반 라인 배수를 적용하고 일반 월 가산액은 신규 월액에 한 번 더한다. |
| cohort | `new_multiplier` 기본 1, `exclude_unconfirmed` 기본 false | `params.new_probability`는 0~1, 기본 1이다. 신규 기대 고객은 신규 고객 수 × 신규 배수 × 확률이다. 제외가 true이고 확률이 1 미만이면 신규 유입은 0이다. 기말 고객은 전월 고객 × (1 − 이탈률) + 신규 기대 고객이다. 기말 고객 × 객단가에 일반 라인 배수·가산액을 적용한다. 소수 고객은 반올림하지 않는다. |

전제사항에서 같은 묶음의 공통 근거는 한 번 표시한다. 확률 0.935는 93.5%로 읽으며 날짜 가정은 달력 날짜로 표시한다. 상각 전용 라인의 금액은 투자·상각 계획에서 조정하며 Sensitivity에 전용 라인의 배수·가산 행을 만들지 않는다.

아래는 `scenarios` 안에 넣는 Up 설정의 예다. `kits`는 price_volume, `projects`는 contracts, `members`는 cohort 매출 ID다. 화면에서는 전제사항의 시나리오 구역 K~M에 Base·Up·Down 값이 있고, G열은 현재 적용값을 보여 준다.

```json
{"Up":{"multipliers":{"kits":1.08},"drivers":{"kits":{"price_multiplier":1.03},
 "projects":{"new_multiplier":1.5,"exclude_unconfirmed":true},
 "members":{"new_multiplier":1.5,"exclude_unconfirmed":false}},
 "basis":"제품 판매수량·단가 변경, 신규 유입 확대"}}
```

예를 들어 전월 고객 100명, 이탈률 2%, 신규 4.5명, 신규 배수 1.5, 확률 0.8이면 기존 고객은 98명이다. 미확정 포함 시 신규 기대 5.4명을 더해 103.4명, 제외 시 기말 98명이다. 확률을 생략하면 1이므로 두 설정 모두 신규 유입 6.75명을 포함한다.

위 Down은 매 추정 월의 임차료를 10만원 높인다. 추가 케이스는 교육 매출을 매월 20만원 높인다. 특별 구축 지원은 6월에만 13만원을 더한다.

| 필드 | 뜻 | 생략 시 |
|---|---|---|
| `cases` | 고정 케이스 1~3(Base/Up/Down) 뒤에 추가할 케이스 배열. 최대 7개 | 빈 배열 |
| `cases[].label, scenario` | 고유 표시명, 기준 시나리오 이름(Base/Up/Down) | 둘 다 필수 |
| `cases[].multipliers, additions` | 시나리오 배수에 곱할 케이스 배수, 시나리오 월 가산액에 더할 케이스 월 가산액(원) | 라인별 1과 0 |
| `extensions` | 별도 확장 시트에서 공급하는 월별 조정 목록 | 빈 배열 |
| `extensions[].line_id, label, monthly` | 대상 라인 ID, 조정명, 추정 월별 가산액(원). 차감은 음수 | ID와 조정명 필수. 금액표 생략 시 빈 객체, 미입력 월 0 |

상각 전용 라인을 제외한 매출·비용 라인에는 수동 조정 행이 있다. 확장 항목이 있으면 해당 라인의 월별 확장 금액을 그 행에 연결한다. 특정 월의 계획 금액 전체는 `manual.params.monthly`에, 특정 월에만 더하거나 뺄 차액은 `extensions[].monthly`에 넣는다.

### Excel 버튼과 자동 호출

Sensitivity 시트의 ‘민감도 갱신’은 `RefreshSensitivity`, ‘기준값 갱신’은 `RefreshBaselines`를 인자 없이 호출한다. 기준값 단추는 저장 전에 차이 셀 수를 보여 주고 예·아니오를 묻는다. 자동화는 `Application.Run("'모델.xlsm'!RefreshBaselinesSilent", "QA")`로 실행한다. 선택 문자열은 호출 구분이며 생략 시 ‘자동 실행’이다. 성공하면 변경 전 차이 셀 수(0 포함)를 숫자로 반환하며 기준값갱신 시트 J7:L7 아래에 실행 시각·차이 셀 수·호출 구분을 한 행씩 기록한다. 오류 시 선택 케이스·기준값·갱신 시각을 복구하고 `ERROR: …` 문자열을 반환한다. 자동 호출자는 반환값의 자료형을 확인한 뒤 저장한다.

완성된 통합 문서는 02a의 기존 이름 15개를 유지한다. 세무 입력 위치는 `META_Inputs`의 시트·주소나 전제사항의 행 이름에서 찾는다. `투자비`와 `BS명세`는 계산 단계 3으로 등록한다. 결과표의 전년 대비에서 비율의 차이는 퍼센트포인트(%p)로 읽는다.

## 확장 모듈

### 설계서에서 월별 조정표 생성하기

1. 기존 동인에 **추가할 차액**을 정한다. 예를 들어 계약 매출 라인 `projects`의 2027년 6월에 13만원을 한 번 더 반영하려면 앞의 예시처럼 `extensions`에 `line_id`, `label`, `monthly`를 적는다. `monthly`는 추정 월별 원 단위 **증감액**이며 음수와 빈 객체를 허용한다.
2. 표준 CLI로 모델을 다시 만든다. 설계서에 확장 항목이 하나라도 있으면 Excel에 `확장조정` 시트가 생성된다. 배열 순서대로 8행부터 조정 항목을 배치한다. 같은 라인의 여러 조정은 해당 월에 합산해 대상 라인의 ‘수동 조정’ 행에 연결한다. 매출은 라인 상세 시트, 비용은 운영비용 시트에서 연결을 확인한다.
3. 예시의 `Unit=1000000`이면 6월 입력 셀과 수동 조정 행은 0.13이다. 설계서와 외부 계산의 단위는 원, **생성된 확장조정 시트에서 편집하는 월별 금액은 표시 단위**다. 시나리오가 바뀌어도 조정 자체는 동일하게 더해진다. 확장 항목이 없는 라인은 상세 시트의 노란 수동 조정 행에서 직접 입력할 수 있다. 투자비의 상각을 배분받는 전용 라인은 조정 대상에서 제외한다.
4. 재생성할 때도 유지할 가정은 `Work/model_spec.json`의 월별 조정액으로 되돌려 적는다. 업종 계산이 외부 원자료에서 이미 끝났으면 그 결과를 월별 증감액으로 공급하는 것만으로 이 경로가 완성된다. 입력 시트와 입력 범위는 엔진이 자동으로 메타 표에 등록한다.

### 사용자가 Excel에서 계산식을 볼 수 있도록 별도 시트 붙이기

표준 설계서가 생성하는 이름은 `확장조정`이다. 회사 고유 계산 시트가 필요할 때는 **생성된 회사 모델의 별도 XLSM 복사본**에서 다음 순서로 작업한다. 이 후처리는 회사 작업 폴더에 보관하고 모델을 다시 만들 때 재적용한다.

1. 설계서에 대상 라인과 조정 이름을 먼저 등록해 출력 행을 확보한다. Excel에서 복사본을 열고 가정·상세 구역에 산식 시트를 하나 만든다. 기간은 `INDEX`의 같은 열 월을 직접 링크한다. 예를 들어 새 시트 `별도조정산식`의 8행에 원 단위 월별 추가금액, 9행에 같은 열 8행 ÷ `Unit`을 둔다. 계산 원천이 수량과 단가이면 9행을 수량 × 원단가 ÷ `Unit`으로 바꾼다. 실제 추가금액이 없는 달의 결과는 0이다.
2. `모델정보`의 `META_Inputs`에서 해당 확장 라벨과 시트명이 `확장조정`인 행을 찾아 월별 주소를 확인한다. 예를 들어 출력 행의 J열을 `='별도조정산식'!J9`로 연결하고 마지막 월까지 같은 열을 참조한다. 연결된 셀은 계산 서식, 실제 편집 셀은 노란 채움·파란 글씨를 사용한다. 본표와 대상 라인의 합계 수식은 그대로 이용한다.
3. `모델정보` 시트의 **통합 문서 범위 이름** `META_Sheets`에 머리글 순서대로 한 행을 추가한다. 예시는 `별도조정산식 | driver | 2 | 월별 추가금액을 표시 단위로 환산`이다. 새 행이 표 바로 아래 빈 행인지 확인하고 **이름 관리자의 참조 대상까지 한 행 늘린다**. 공간이 모자라면 모델정보에 필요한 행을 확보한 뒤 기존 네 메타 표의 참조 주소와 머리글을 다시 확인한다. 목차의 가정·상세 목록에도 시트명, 설명, 내부 바로가기를 추가한다.
4. `META_Inputs`의 열 순서는 `group, label, sheet, cell, description`이다. 연결한 출력 행 전체가 수식이 되었으면 기존 등록 행을 실제 새 입력으로 옮긴다. 예를 들어 첫 월 J열, 마지막 월 U열이면 `확장조정 | 월별 추가금액 (원) | 별도조정산식 | J8:U8 | 원 단위 입력액`이다. 월 범위는 해당 파일의 `META_Info.first_month_col`과 `last_month_col`에서 확인한다. 일부만 수식으로 바꿨으면 남은 편집 구간과 새 입력 구간을 따로 등록한다. 입력 행을 추가했다면 `META_Inputs` 범위도 확장한다. 기존 `META_Info`와 `META_Checks`의 내용, `Unit`·`Scenario`·`LastActual`, `SN_*`·`BL_*` 이름 및 VBA 버튼 연결을 보존한다.
5. Excel에서 전체 계산 후 한 추정 월의 새 원화 입력에 `Unit`만큼 더해 대상 라인의 수동 조정과 최종 금액이 표시 단위 1만큼 증가하는지 확인한다. 입력을 원래 값으로 복원한다. 가정 확정 후 **민감도 갱신**으로 케이스별 결과를 저장하고 **기준값 갱신**의 차이 개수를 확인해 기준값을 저장한다. 선택 케이스가 복원되고 모델 검증 결과가 OK인지 확인한다.
6. Excel에서 매크로 사용 통합 문서(.xlsm)로 저장하고 다시 연다. 두 단추와 통합 문서 이름이 유효한지 확인한다. 아래 명령에서 `company-extension.xlsm`을 실제 후처리 파일명으로 바꾼다. 같은 정규화 자료로 검증하고 구조도에 새 시트, 입력 및 연결이 표시되는지 확인한다.

```text
python scripts/verify_model.py Output/company-extension.xlsm --data Work/normalized --out Work/verify_report.md
python scripts/make_model_map.py Output/company-extension.xlsm --out Output/company-extension_Map.html
```

## 정규화 CSV와 설계서 연결

첫 줄은 아래의 필수 열을 정확히 한 번씩 포함한다. debt, headcount, sales_volume에는 지정된 선택 열을 추가할 수 있으며 선택 열의 빈 셀은 생략으로 처리한다. 열 순서는 바꿀 수 있다. 쉼표 구분 UTF-8(BOM 허용), 금액은 천 단위 쉼표 없는 원 단위 정수, 비율은 소수로 입력한다. 수량·인원·개당 가격은 0 이상 소수를 허용한다. 필수 숫자 셀에 0을 입력하면 실제 0으로 읽는다. `note, memo, counterparty`의 빈 칸은 빈 문자열로 읽는다.

| 파일·열 | 모델 연결과 검사 |
|---|---|
| `is_monthly.csv` · `month,account,section,amount` | 필수. 월 발생액. 구분은 매출·매출원가·판관비·영업외수익·영업외비용·법인세. 비용은 양수 또는 0. 모든 실적 월에 자료가 필요하며 월·구분·계정 조합은 유일하다. |
| `bs_monthly.csv` · `month,account,section,amount` | 월말 잔액. 구분은 유동자산·비유동자산·유동부채·비유동부채·자본. 차감 계정은 음수. 월·구분·계정 조합이 유일하고 제공한 월마다 대차가 일치해야 한다. BS 추정에는 마감 월 잔액이 필요하며 그 이전 BS는 있는 월만 제출할 수 있다. |
| `debt.csv` · `facility,lender,type,balance,rate,maturity,note` | 약정 ID, 대주, 유형(term/revolver/bond/lease), 마감 월말 잔액(원), 연이율(0~1), 만기 월, 비고. 약정 ID는 유일하다. 선택 열 `at_maturity`는 repay 또는 rollover. 만기는 YYYY-MM 또는 실제 달력 날짜 YYYY-MM-DD이며, 일자는 검증 후 해당 월로 환산한다. |
| `debt_schedule.csv` · `facility,month,principal` | 등록 약정 ID별 월 상환원금(원). 약정·월 조합은 유일하다. 만기를 넘는 상환, 마감 이후 상환 합계가 마감 잔액을 넘는 입력은 오류다. 계획 종료 후의 약정상 상환도 기재할 수 있다. |
| `journal.csv` · `date,account,counterparty,debit,credit,memo` | 실제 달력 날짜(YYYY-MM-DD), 원천 계정·거래처, 차변·대변(0 이상 원), 적요. 분개장으로 손익을 만들 때는 월별 집계 결과를 필수 손익 CSV에 넣는다. |
| `revenue_items.csv` · `item,line,start,end,amount,probability,note` | 계약 ID, contracts **매출 ID**, 시작·종료 월, 월매출(원), 실현 확률(0~1), 비고. 월 금액을 양 끝 월까지 적용한다. 같은 라인의 계약 ID는 유일하다. |
| `headcount.csv` · `role,count,monthly_cost,start,end` | 직군, 인원(0 이상, 소수 가능), 1인당 월 비용(원), 시작·종료 월. CSV의 직군·인원·단가·기간을 사용한다. 선택 열 `raise_from`은 인상 개시 월이다. 직군별 `annual_raise`는 설계서에서 지정한다. 직군·시작·종료 월 조합은 유일하다. |
| `sales_volume.csv` · `month,line,quantity,price` | 실적 또는 추정 월별 수량과 개당 가격(원). `line`은 price_volume 또는 activity 매출 ID. 월·라인 조합은 유일하다. 네 필수 열에 `activity` 열을 추가할 수 있다. activity 라인은 모든 실적 월에 활동량을 제공한다. |
| `metrics_monthly.csv` · `month,metric,line,value` | 실적 월, 등록 지표 ID, 지표에 연결된 활동 매출 ID, 원천 지표 물량. 월·지표·라인 조합은 유일하며 값은 0 이상이다. |
| `fixed_assets.csv` · `asset_class,cost,accumulated_dep,method,rate_or_life` | 자산군, 취득원가, 상각누계액(양의 차감액 또는 0), 상각 방법, 내용연수 또는 비율. 정액법은 개월, 정률법은 연 소수 비율. 자산대장을 근거로 `investment.asset_classes[].opening`과 기존 자산 가정을 작성한다. 자산군의 잔여월수는 마감 자료에서 구해 설계서에 별도로 입력한다. |

손익 CSV는 모든 계정에 매달 0원 행을 만들 필요가 없다. 보고가 완전한 달에 특정 계정 행이 없으면 해당 계정의 당월 금액은 0이다. 실적 월 전체가 빠지면 검증 오류이므로 거래가 전혀 없었던 달도 실제 영업 계정의 0원 행 등으로 그 달이 보고됐음을 표시한다. 원자료가 미확인인 달을 0원 행으로 채우지 않는다. 수량·단가 월별 자료는 빈칸과 0의 의미가 다르다. 월 매출이 0인 계획을 명시하려면 해당 월 수량 0 등 실제 값을 입력하고, 기준 가정으로 돌아갈 월은 지정값을 생략한다.

손익·BS의 월은 실적 구간에 있어야 한다. 월별 계획 금액은 추정 구간에 있어야 한다. 계약·직군의 시작 월은 종료 월 이하여야 한다. 차입 약정과 상환표는 각각 CSV 또는 설계서에서 공급할 수 있다. debt CSV가 있으면 약정별 설계서 값은 ID로 보완한다. 양쪽에 있는 필드는 일치해야 한다. 상환표를 양쪽에 채우면 약정·월별 원금 및 행 집합이 같아야 한다. 행 순서는 무관하다.

## Python 호출

```python
from spec_io import load_inputs

spec, data = load_inputs("Work/model_spec.json", "Work/normalized")
unit = spec["unit"]
actual_rows = data["is_monthly"]
```

`spec`에는 기본값과 최종 직군·차입 계획이 들어간다. `data`는 위 파일의 확장자를 뺀 이름을 키로 쓰며, 각 값은 열 이름으로 접근하는 행 딕셔너리의 목록이다. 선택 파일이 없으면 빈 목록이다. 금액과 인원은 숫자, 월과 날짜는 문자열이다. 검증 오류는 `ValueError`로 전달되며 설계서 필드, 파일·행 또는 오류를 일으킨 계정·ID·월을 메시지에서 확인할 수 있다.


설계서에 직접 적는 약정 만기는 YYYY-MM이다.


## Excel 입력 범위와 검증

결과 화면의 ‘모델 검증’은 선택한 케이스의 계산 결과와 원본 입력 범위를 함께 집계한다. 입력 항목이 NO이면 `검증` 시트 하단 ‘입력 검증 상세’에서 오류가 난 시트와 셀 범위를 확인한다. 전제사항의 시나리오 입력은 Base·Up·Down 모두 검사한다. Excel의 직접 입력 제한을 거치지 않는 붙여넣기와 내용 삭제에도 같은 범위 검사가 적용된다.

| 입력 항목 | 허용값 |
|---|---|
| 최소 보유현금, 한도대출 한도, 기초 현금 | 0 이상 숫자. 필수 입력 |
| 신규 조달·추가 한도·개별 약정 연이율 | 0~100%. 필수 입력 |
| 만기 처리 | 전체 정책은 0 또는 1. 개별 약정은 −1(전체 정책 적용), 0(상환), 1(연장) |
| 공통·직군 임금 인상률, 활동당 수량·물량당 원가 연 증감률 | −100% 이상 숫자. 임금 인하율도 입력할 수 있다 |
| 활동 매출 `price_steps[].pct` | −100% 초과 숫자. 동결은 0, 5% 인하는 −0.05 |
| 활동량·활동당 수량·가격 시나리오 배수 | 0 이상. 효율 배수는 0 초과. 월별 활동·수량·가격 덮어쓰기의 빈칸은 기준 가정 적용 |
| 월별 배당·자산 취득·수취 전용 직접 매출 | 추정 월마다 0 이상 숫자. 미지급·미취득·미수취 월에는 0 입력 |
| 정수 선택 목록 | 0/1 및 −1/0/1 목록의 입력 칸은 Excel의 일반 숫자 서식을 쓴다. 0.5를 그대로 표시하므로 목록 제한과 입력 검증이 모두 소수 입력을 찾아낸다. 사업부 계획의 비어 있는 예비 행은 허용하며, 한 칸이라도 기입한 행에는 적용 0 또는 1이 필요하다 |
| 취득 수량·단가 | `investment.asset_classes[].whole_units: true`는 정수 단위 취득에 사용한다. 수량은 0 이상 정수, 취득 월 단가는 0 초과다. 다른 자산군에는 0 이상 소수 수량도 허용한다 |
| 직접 매출의 부호 | `driver: "manual"`의 `params.nonnegative: true`는 지원금 등 수취 전용 라인에 지정한다. 기본값은 false로 환입 등 음수 매출을 허용한다 |
| 월별 비용 보정·수동 조정·증자 및 감자 | 양수·0·음수 사용. 활동 원가 보정, 수동 조정의 빈칸은 해당 월 보정 0 |
