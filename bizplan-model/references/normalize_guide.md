# 원자료 정규화 안내

회사마다 파일 형식이 다르다. 스크립트는 표준 CSV만 읽으므로, 원자료를 네가 읽고 `Work/normalized/`에 옮겨 적는다. 이 단계의 실수는 뒤에서 발견하기 어렵다. 옮긴 뒤 반드시 원자료 합계와 대사한다.

## 공통 규칙

- 인코딩 UTF-8(BOM 포함), 쉼표 구분, 첫 행은 열 이름
- 금액은 **원 단위 정수**. 원자료가 천원·백만원 단위면 곱해서 원으로 바꾼다. 단위는 시트 머리말, 파일명, 숫자 크기로 확인하고 불확실하면 사용자에게 묻는다
- 월은 `YYYY-MM`
- 손익은 **월 발생액**. 원자료가 누계(연초부터 합산)면 전월 누계를 빼서 월 발생액으로 바꾼다. 1월 값이 12월보다 갑자기 작아지는 패턴이면 누계다
- 비용은 양수로 적는다. 원자료가 비용을 음수로 표기하면 부호를 바꾼다
- 소계·합계 행은 옮기지 않는다. 계정 단위 행만 옮긴다. 소계는 대사에만 쓴다
- 금액이 0인 달도 행을 넣는다. 그래야 "그 달에 0이었다"와 "자료가 없다"가 구별된다. 실적 기간 내내 0인 계정은 옮기지 않아도 된다

## 파일별 형식

### `is_monthly.csv` (필수)

`month, account, section, amount`

`section`은 `매출, 매출원가, 판관비, 영업외수익, 영업외비용, 법인세` 중 하나다. 원자료의 구분(매출총이익 위/아래, 영업이익 위/아래)을 따른다. 제조원가명세서가 따로 있으면 제조원가 계정들을 `매출원가`로 넣고 재고 증감 조정도 한 계정으로 넣어 매출원가 합계가 원자료와 맞게 한다.

계정 이름은 원자료 그대로 쓴다. 비슷한 계정을 네 판단으로 합치지 않는다. 합치는 것은 설계서에서 "모델 라인"으로 한다. 그래야 실적 대사가 계정 단위로 된다.

### `bs_monthly.csv` (권장)

`month, account, section, amount`

`section`은 `유동자산, 비유동자산, 유동부채, 비유동부채, 자본`. 월말 잔액이다. 감가상각누계액, 대손충당금 같은 차감 계정은 음수로 적는다. 매월 자산 합계 = 부채 합계 + 자본 합계인지 확인한다. 맞지 않으면 빠진 계정이 있다.

기타 비영업 자산·부채의 추정 증감을 계획할 때도 실적 마감 월의 계정명·구분·잔액을 보존한다. 대여금 잔액 500만원 중 100만원 회수 예정이면 마감 BS에는 실제 잔액 500만원, 설계서 `other_items`에는 회수 월의 증감 −100만원을 넣는다. 자본 계정은 이익잉여금, 납입자본과 기타 자본을 원 계정대로 옮긴다. 감자 계획을 검증하려면 마감 월의 납입자본 계정을 식별할 수 있어야 한다. 자본 합계만 있는 자료는 모델에 기초 미구분으로 표시한다. 실적 배당의 자본 효과는 이미 실적 BS에 들어 있고 계획 배당·증자·감자는 설계서 `equity`에 월별로 적는다.

### `debt.csv`, `debt_schedule.csv`

`facility, lender, type, balance, rate, maturity, note` / `facility, month, principal`

`balance`는 실적 마감 월 말 잔액, `rate`는 연 이율(소수, 4.5%는 0.045), `type`은 `term`(분할·만기 상환), `revolver`(한도대출), `bond`(사채), `lease`. 상환 스케줄이 있으면 회차별 원금을 `debt_schedule.csv`에 적는다. 스케줄이 없고 만기만 있으면 만기 일시 상환으로 두고, 연장 여부는 사용자에게 묻는다. `debt.csv`의 잔액 합계가 재무상태표의 차입금 합계와 맞는지 확인한다.

### `journal.csv` (선택)

`date, account, counterparty, debit, credit, memo`

분개장이나 총계정원장을 받았을 때만 만든다. 손익계산서를 받지 못했으면 분개장에서 `is_monthly.csv`를 집계한다. 손익 계정의 월별 (대변 − 차변)이 수익, (차변 − 대변)이 비용이다. 계정과목표로 계정의 구분을 정한다. 결산 대체 분개(손익 계정을 이익잉여금으로 마감하는 분개)는 빼야 손익이 0이 되지 않는다.

### `revenue_items.csv` (선택)

`item, line, start, end, amount, probability, note`

계약, 프로젝트, 현장, 고객 단위의 매출 목록이 있을 때 만든다. `amount`는 월 금액(원)이다. 총액만 있으면 기간으로 나눈다. `probability`는 확정이면 1, 협의 중이면 사용자가 준 확률을 쓰고 없으면 묻는다.

### `sales_volume.csv` (선택)

필수 열은 `month, line, quantity, price`, 선택 열은 `activity`다.

제품·서비스별 판매 수량과 단가 자료가 있을 때 만든다. 실적 월과 계획 월을 모두 적을 수 있다. `line`은 설계서의 매출 라인 ID다. 수량 × 단가가 그 달 매출 계정 금액과 맞는지 확인한다. 맞지 않으면(에누리, 환입 등) 차이를 별도 매출 라인으로 둔다.

활동량 기반 매출 라인에는 `activity`에 그 달의 실제 활동량, `quantity`에 판매 수량, `price`에 판매 수량 한 단위당 원 단가를 넣는다. 월·라인별로 한 행만 적는다. 같은 달에 여러 기록이 있으면 활동량과 수량을 각각 합산하고 원 단가는 매출 합계 ÷ 수량 합계로 가중 계산한다. 단가·수량·활동량에는 0 이상 소수를 쓸 수 있다. 기존 `price_volume` 라인은 네 필수 열을 그대로 사용하고, 활동 라인과 파일을 함께 쓸 때는 해당 활동량 셀을 비울 수 있다.

```csv
month,line,quantity,price,activity
2026-11,A,600,1000,100
2026-12,A,0,1000,0
2027-03,A,672,1050,112
```

A는 11월 활동 100회, 활동당 판매 6개, 월매출 600,000원이다. 활동 라인은 첫 실적 월부터 마감 월까지 모든 달의 실제 값을 확인한다. 활동량이 0이면 판매 수량도 0이어야 한다. 활동했지만 판매가 없으면 양의 활동량과 판매 수량 0을 입력한다. 관측 자료가 빠진 달은 원자료에서 보완한다. 추정 월 행은 선택이며 활동량, 수량에서 구한 활동당 수량, 단가를 함께 지정한다. 특정 요소만 계획이 있을 때는 설계서의 해당 요소 `monthly`에 적는다.

### `metrics_monthly.csv` (선택)

`month, metric, line, value`

월·지표 ID·활동 매출 라인 ID마다 원자료에서 확인한 물량을 한 행으로 적는다. 같은 지표에는 하나의 측정 단위를 일관되게 쓴다. `value`는 월 합계이며 0 이상 소수를 허용한다. 서로 다른 라인의 물량을 합친 총계 행은 넣지 않는다.

```csv
month,metric,line,value
2026-11,work,A,2400
2026-12,work,A,0
```

11월 지표 2,400을 같은 달의 활동량 100으로 나누면 활동당 계수 24다. 계수를 실적에서 구하는 `{"base":"actual"}` 라인은 모든 실적 월의 관측 지표가 필요하다. 활동과 지표가 모두 0인 관측 월의 계수는 0이다. 설계서에서 상수 계수를 쓰면 CSV 없이도 산출하며, 관측 지표를 제공한 실적 월에는 그 값이 우선한다. 추정 월의 계수 변경은 설계서의 `metrics[].lines.<라인ID>.monthly`에 넣는다. 이는 `{"base":"actual"}` 형식의 계수에서 지원한다.

### 소비량 실적과 단가 계획

`consumption` 비용 라인의 실적 단가 참고값을 표시하려면 사용량 자료에서 그 계정에 대응하는 월 실사용량을 구해 설계서 `params.actual_usage`에 넣는다. 예를 들어 계정에 배정한 실적 비용이 630,000원이고 같은 달 확인한 실제 사용량이 350이면 표시 단가는 1,800원/단위다. `metrics_monthly.csv`에는 활동 지표를 적고, `actual_usage`에는 소비 단위를 적는다. 두 값의 단위를 분리한다. 실사용량 자료가 없는 달은 생략한다. 추정 단가·보조·효율의 월별 변경 계획은 각각 `params.price`, `subsidy`, `efficiency`에 넣고 첫 추정 월의 값과 이후 변경 월을 적는다.

### `headcount.csv`, `fixed_assets.csv` (선택)

`role, count, monthly_cost, start, end` / `asset_class, cost, accumulated_dep, method, rate_or_life`

급여 자료에서 개인 이름은 옮기지 않는다. 직군과 인원 수, 기준 1인당 월 비용(원), 적용 기간을 옮긴다. 최초 인상 월은 선택 CSV 열 `raise_from` 또는 설계서에 적는다. 직군별 연 인상률은 설계서 `wages.roles[].annual_raise`에 소수로 입력하고, 협약의 소급 적용 월·정산 월·손익 인식 정책은 `wages.retro`에 넣는다. 같은 직군으로 채용 기간이 나뉘면 정책을 적용할 CSV 행이 한 개가 되도록 시작·종료 월을 명시한다.

자산대장 `fixed_assets.csv`에는 취득원가(원), 양수 상각누계액, 상각법과 내용연수(정액, 개월) 또는 연 상각률(정률, 소수)을 넣는다. 실적 마감 유형자산 순액과 대사한 뒤 `investment.asset_classes[].opening`에 자산군별 취득가·누계액·잔여 개월을 옮긴다. 같은 종류라도 잔여기간이 다른 자산 묶음은 구분한다. 추정 취득의 수량·단가는 설계서 `purchases`에 추정 월별로 적는다. 정률 자산군은 설계서에서 내용연수와 연율을 모두 지정한다.

## 대사 (반드시 한다)

옮긴 뒤 다음을 확인하고 결과를 `Work/normalized/_reconcile.md`에 적는다.

| 항목 | 비교 |
|---|---|
| 월별 매출 합계 | `is_monthly.csv`의 매출 합계 = 원자료의 매출액 |
| 활동 매출 라인 | 월별 활동량 × 활동당 판매 수량 × 개당 원 단가 = 그 라인에 배정한 실적 매출 계정 합계 |
| 실적 지표 | `metrics_monthly.csv`의 라인별 월 물량과 월별 라인 합계 = 원자료의 같은 지표 |
| 월별 영업이익 | 매출 − 매출원가 − 판관비 = 원자료의 영업이익 |
| 월별 당기순이익 | 원자료의 당기순이익 |
| 자산 총계 | `bs_monthly.csv`의 자산 합계 = 원자료의 자산 총계 |
| 차입금 | `debt.csv` 잔액 합계 = 재무상태표의 차입금 |

### 손익계산서 없이 분개장만 받았을 때

비교할 손익계산서가 없으므로 분개장 안의 통제 값으로 대사한다.

| 항목 | 비교 |
|---|---|
| 전표별 차대 | 전표마다 차변 합계 = 대변 합계 |
| 월계 | 분개장의 월계·누계 행이 있으면 옮긴 행의 월 합계와 일치(월계 행 자체는 옮기지 않는다) |
| 계약·청구 | 계약 목록의 월 금액 합계 = 그 달 매출 계정 금액 |
| 차입 | 차입 계정 잔액 = 약정서의 잔액 |
| 현금 | 예금 계정의 누계 잔액이 음수가 되는 달이 없는지 |

기초 잔액 전표(전기 이월)는 손익에 넣지 않고 잔액 계산에만 쓴다. 기초 전표의 날짜를 실적 기간의 시작으로 보지 않는다.

분개장에 재무상태표 계정과 기초 잔액이 모두 있으면 월말 잔액을 누적해 `bs_monthly.csv`를 만들 수 있다. 만들지 여부는 사용자에게 묻는다. 만들면 매월 대차가 맞는지 확인한다. 만들지 않으면 실적 마감 월의 예금 잔액과 차입 잔액만 분개장에서 구해 설계서의 기초 현금과 약정 잔액으로 쓴다.

### 차이가 있을 때

차이가 1원이라도 있으면 원인을 찾는다. 흔한 원인은 소계 행을 계정으로 옮긴 것, 단위 혼동, 누계와 월 발생액 혼동, 숨겨진 행·시트, 부호다. 원자료 자체가 맞지 않는 경우(원자료의 합계 수식 오류 등)에는 어느 쪽을 따랐는지 적고 사용자에게 알린다.
