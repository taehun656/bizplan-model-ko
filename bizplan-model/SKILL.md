# 사업계획 재무모델 스킬

회사의 실적 자료로 사업계획 재무모델을 만든다. 산출물은 세 가지다.

1. `Output/<회사>_BP<연도>_Model.xlsm` — 매크로 포함 Excel 모델
2. `Output/<회사>_BP<연도>_Model_Map.html` — 모델 구조도(입력 → 계산 → 산출)
3. `Output/00_결과요약.md` — 결과, 가정, 확인이 필요한 사항

## 일하는 원칙

**판단은 네가 하고, 조립은 스크립트가 한다.** Excel 파일을 직접 만들거나 openpyxl로 고쳐 저장하지 않는다. 모델은 `scripts/build_model.py`가 설계서(`model_spec.json`)를 읽어 만든다. 네가 할 일은 자료를 읽고, 회사를 이해하고, 설계서를 정확히 쓰는 것이다. 이렇게 나눈 이유는 재무모델의 수식 수천 개를 매번 새로 쓰면 실행할 때마다 품질이 달라지고 검증할 수 없기 때문이다.

**모르는 것은 지어내지 않는다.** 자료에 없는 숫자는 사용자에게 묻거나, 실적에서 계산한 값을 쓰고 근거를 남기거나, "확인 필요"로 표시한다. 사업계획은 의사결정에 쓰이므로 출처 없는 숫자 하나가 전체의 신뢰를 깎는다.

**사용자는 재무 책임자다.** 회계와 재무 용어는 그대로 쓰되, 프로그래밍 용어(JSON, 스키마, 스크립트 이름)는 사용자에게 보여 주지 않는다. "설계서를 썼습니다"가 아니라 "매출은 제품 3종의 수량 × 단가로, 판관비는 고정비에 물가상승률을 적용해 추정하겠습니다"처럼 내용으로 말한다.

**사용자의 데이터는 PC 밖으로 내보내지 않는다.** 이 스킬의 스크립트는 네트워크를 쓰지 않는다. 너도 자료의 내용을 웹 검색이나 외부 서비스에 넣지 않는다.

사용자의 언어로 답한다. 금액 단위는 기본 백만원이다.

## 진행 순서

각 단계 끝의 **확인** 표시는 사용자 답을 받고 넘어가는 지점이다. 나머지는 멈추지 않고 이어서 한다.

### 0. 환경 확인

`python scripts/check_env.py`를 실행한다. 부족한 것이 있으면 사용자에게 무엇을 설치해야 하는지 알려 주고 멈춘다. 기존 작업 폴더에 `Work/model_spec.json`이 이미 있으면 새로 시작하지 말고 "수정 요청 처리"로 간다.

### 1. 자료 요청 — **확인**

작업 폴더에 `Input`, `Work`, `Output`을 만든다. `references/intake_checklist.md`를 읽고 그 목록을 사용자에게 보여 준다. 필수, 있으면 좋은 것, 없어도 되는 것을 구분하고, 없을 때 모델이 어떻게 달라지는지 한 줄씩 붙인다. 함께 묻는다.

- 계획 대상 연도와 실적 마감 월
- 회사가 이미 정한 목표나 예산이 있는지(있으면 그 파일도 `Input`에)
- 평소 쓰는 재무모델 양식이 있는지(있으면 견본 파일을 `Input`에)

사용자가 자료를 넣었다고 할 때까지 기다린다.

### 2. 자료 점검과 정규화

1. `python scripts/inventory_inputs.py Input --out Work/inventory.md`를 실행하고 결과를 읽는다.
2. 원자료를 직접 열어 본다. 목록만 믿지 않는다. 병합 셀, 소계 행, 단위(원/천원/백만원), 부호 규칙, 누계인지 월 발생액인지를 확인한다.
3. `references/normalize_guide.md`에 따라 `Work/normalized/`에 표준 CSV를 쓴다. 옮겨 적은 뒤에는 원자료의 합계와 대사한다(매출 합계, 영업이익, 자산 총계). 맞지 않으면 원인을 찾을 때까지 다음 단계로 가지 않는다. 여기서 틀리면 뒤의 모든 숫자가 틀린다.
4. 빠진 자료를 정리해 사용자에게 알린다. 필수 자료가 없으면 요청하고, 권장 자료가 없으면 어떤 가정으로 대신할지 말하고 계속한다.

### 3. 회사 이해와 모델 설계 — **확인**

1. `python scripts/profile_history.py --data Work/normalized --out Work/profile.md`를 실행하고 읽는다.
2. `references/driver_guide.md`를 읽고 판단한다: 이 회사는 무슨 사업을 하는가, 매출은 무엇에 따라 움직이는가, 어떤 비용이 매출을 따라가고 어떤 비용이 고정인가. 업종 이름을 맞히는 것이 목적이 아니다. 매출 라인마다 맞는 동인 유형을 고르는 것이 목적이다.
3. `references/spec_schema.md`를 읽고 `Work/model_spec.json`을 쓴다. 가정값마다 근거(`basis`)를 적는다. 근거는 "실적 최근 12개월 평균", "사용자 지정", "차입 약정표" 같은 출처다.
4. 사용자에게 설계를 설명하고 확인받는다. 표 하나와 질문 몇 개면 된다.
   - 매출 라인별 추정 방식과 핵심 가정
   - 비용의 변동/고정 구분과 기준값
   - 반드시 사용자가 정해야 하는 것: 최소 보유현금, 한도대출 한도, 만기 도래 차입의 처리(약정별 연장/상환), 임금 인상률, 투자 계획, Up·Down 시나리오의 정의
   - 법인세는 법정 누진세율과 신고자료를 사용한다. 중소기업 여부, 결산월, 이월결손금, 반복되는 세무조정 및 연중 마감일까지 납부한 국세·지방세를 확인한다.
   - 세액공제는 직전 결산의 세액공제조정명세서에서 기준월과 발생연도·유형별 미공제 잔액을 받는다. 신규 공제 예상액, 각 유형의 최저한세·농어촌특별세 적용 여부, 중소기업 졸업 유예율을 확인해 `tax.credit_vintages`, `tax.new_credits`, `tax.minimum_tax`에 적는다. 계산 순서와 근거 조문은 `references/tax_rules_kr.md`에 있다.
   - 계약 매출: 기존 계약이 계획 기간 안에 만료되면 갱신될 비율과 갱신 기간을 묻는다. 계약을 손으로 복제하지 않고 갱신 확률로 넣는다
   - 운전자본: 재고와 매입채무가 어떤 비용의 며칠분인지(프로파일이 후보를 제시한다) 확인한다. 한도대출 한도는 이미 쓰고 있는 잔액을 포함한 총 한도로 받는다
   - 실적에는 있는데 사용자가 말하지 않은 것: 매달 반복되는 투자 지출, 영업외수익, 상각이 끝나 가는 자산(`driver_guide.md` 4-1절). 계획에 넣을지 묻는다
   - 네 판단에 자신이 없는 부분과 그 이유

사용자가 고치라고 한 것을 설계서에 반영한다. 사용자가 "알아서 하라"고 하면 실적 기반 기본값으로 진행하되 결과 요약의 "확인 필요"에 남긴다.

### 4. 모델 생성

```
python scripts/build_model.py --spec Work/model_spec.json --data Work/normalized --out Output/<회사>_BP<연도>_Model.xlsm
```

콘솔에는 성공·실패와 경고 수만 나온다. 경고와 오류의 내용은 산출 파일 옆의 `build_log.md`에 있으니 성공했어도 읽는다. 경고는 대부분 사용자에게 확인할 사항이다. 기존 산출 파일은 빌드를 시작할 때 `.prev`로 옮겨지고, 실패하면 새 파일은 생기지 않는다.

오류가 나면 로그를 읽고 설계서를 고쳐 다시 실행한다. 엔진 스크립트 자체는 고치지 않는다. 엔진이 지원하지 않는 업종 고유 로직이 꼭 필요하면 `references/spec_schema.md`의 "확장 모듈" 절을 따른다.

### 5. 검증

```
python scripts/verify_model.py Output/<파일>.xlsm --data Work/normalized --spec Work/model_spec.json --out Work/verify_report.md
```

`--spec`을 주면 모델이 설계서보다 오래된 경우 "낡은 모델"로 실패한다. 설계서를 고친 뒤 다시 빌드하지 않은 것이므로 4단계를 다시 한다. 보고서 맨 위에 실패·경고 건수와 목록이 있다.

실패 항목이 있으면 원인을 찾아 설계서나 정규화 자료를 고치고 4단계부터 다시 한다. 검증을 통과시키려고 검사 기준을 낮추거나 검증 항목을 빼지 않는다. 고칠 수 없는 실패는 그대로 사용자에게 보고한다.

스크립트 검증과 별도로 결과가 상식에 맞는지 직접 본다: 계획 연도 매출과 이익률이 실적 추세와 이어지는가, 실적 마지막 달과 추정 첫 달 사이에 설명되지 않는 단절이 없는가, 현금이 터무니없이 쌓이거나 모자라지 않는가. 이상하면 가정을 다시 본다.

### 6. 구조도와 결과 요약

```
python scripts/make_model_map.py Output/<파일>.xlsm --out Output/<파일>_Map.html
```

`Output/00_결과요약.md`를 쓴다. 구성은 다음과 같다.

1. 산출물 목록
2. 결과: 직전 실적 연도, 당해 예상(실적 마감이 연중일 때만. 연말에 마감했으면 이 열은 없다), 계획 연도의 매출·EBITDA·영업이익·법인세·순이익·기말 차입금·기말 현금, 시나리오 비교. 이월세액공제를 적용한 모델은 연도별 공제 사용액과 기말 잔액도 제시한다.
3. 자금: 현금 부족 시점과 규모, 한도대출 사용, 신규 조달 필요액, DSCR
4. 주요 가정과 근거
5. 확인이 필요한 사항(우선순위순)
6. 검증 결과: 통과한 것, 하지 못한 것

### 7. 사용자에게 보고

짧게 보고한다. 결과 숫자 몇 개, 가장 중요한 위험 하나, 확인이 필요한 사항, 파일 위치. 그리고 모델 사용법을 알려 준다.

- 케이스는 `Sensitivity` 시트의 케이스 선택 칸에서 고른다.
- 가정은 `전제사항` 시트의 노란 칸에서 바꾼다.
- 가정을 바꾼 뒤 `민감도 갱신` 단추를 눌러야 비교표가 바뀐다.
- `기준값 갱신` 단추는 가정을 확정했을 때만 누른다. 검증의 비교 기준을 현재 값으로 덮어쓰기 때문이다.

## 수정 요청 처리

이미 모델이 있는 폴더에서 사용자가 가정 변경, 실적 월 추가, 항목 추가를 요청하면 `Work/model_spec.json`과 `Work/normalized/`를 고쳐 4~6단계를 다시 실행한다. 이전 산출물은 `Output/_archive/`로 옮기고 버전 번호를 올린다(빌드가 남기는 `.prev` 파일은 직전 한 벌뿐이라 보관용이 아니다). 사용자가 Excel에서 직접 고친 내용이 있으면 덮어쓰기 전에 무엇이 사라지는지 알리고 확인받는다.

## 회사별 맞춤

작업 폴더에 `company_profile.md`가 있으면 먼저 읽는다. 회사가 고정해 둔 계정 매핑, 양식 선호, 보고 단위, 승인된 가정이 들어 있다. 이 파일의 내용은 이 스킬의 기본값보다 우선한다. 첫 실행이 끝나면 다음 실행에서 다시 묻지 않도록, 이번에 사용자가 정한 것들을 `company_profile.md`로 저장할지 물어본다. 형식은 `references/company_profile_template.md`를 따른다.

## 실행할 때 주의

- 이 문서의 `scripts/...`는 이 스킬 폴더 안의 경로다. 명령은 사용자의 작업 폴더에서 실행하고 스크립트는 스킬 폴더의 전체 경로로 부른다(예: `python "<스킬 폴더>\scripts\build_model.py" --spec Work\model_spec.json ...`). `Work`, `Input`, `Output`은 작업 폴더 기준이다.
- 모델 생성이 실패하면 이전 산출 파일로 검증이나 구조도를 돌리지 않는다. 실패 원인을 `build_log.md`에서 읽고, 설계서 탓이 아니면 한 번 다시 실행한다.
- Windows 콘솔은 한글이 깨질 수 있다. 스크립트 결과는 `--out`으로 지정한 파일을 읽어서 확인한다.
- 스크립트는 숨은 Excel을 따로 띄워 쓴다. 사용자가 열어 둔 Excel 창이나 프로세스를 닫지 않는다.
- 검증 보고서의 "경고"는 실패가 아니다. 다만 하나씩 원인을 확인하고, 가정 탓이면 고치고, 사업상 이유가 있으면 결과 요약에 그 이유를 적는다.

## 참고 문서

같은 모회사가 보유한 두 곳 이상의 법인 모델을 합산할 때는 `scripts/combine_models.py`를 사용한다. 원본 파일을 각각 보관하고 합산 파일을 별도로 만든다. 입력 조건, 제거 CSV, 원본 재대조 명령은 [법인별 사업계획 합산](references/combine_guide.md)을 따른다.

| 파일 | 언제 읽는가 |
|---|---|
| `references/intake_checklist.md` | 1단계. 자료 요청 목록 |
| `references/normalize_guide.md` | 2단계. 원자료를 표준 형식으로 옮길 때 |
| `references/driver_guide.md` | 3단계. 업종과 동인 판단 |
| `references/spec_schema.md` | 3~4단계. 설계서 작성 |
| `references/format_rules.md` | 산출 Excel의 구성을 사용자에게 설명하거나 확장 시트를 붙일 때 |
